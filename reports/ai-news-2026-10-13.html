01
TestJack: Should you trust the results in coding benchmarks? Agentic Coding Benchmarks Auditing via Evaluator Evolution
Coding benchmarks still judge correctness by fixed unit tests, which under-constrain the task and let agents score by adapting to the evaluator rather than solving the problem. TestJack audits trials by generating tests that target the prompt requirements and evolve them against observed failure modes, exposing patches that pass every original test while missing required behaviour. The upshot: headline benchmark gains on agentic coding are partly measurement artefact. [benchmarks, reward-hacking, evaluation]

02
Returning to Development States: When Full Sandbox Snapshots Help Coding Agents
Retry-from-scratch wastes the machine state a coding agent built before failing — databases, services, runtime side effects that no diff captures. The authors run Go-Explore-style search over full Daytona snapshots and show higher, cheaper solve rates when progress lives outside the repository. Full-snapshot search pays off specifically for long-horizon work spanning multiple services. [agents, sandboxing, search]

03
PolyCodeEval: Benchmarking Multilingual Code Generation from Functions to Repositories
Code-generation benchmarks are fragmented across languages, granularity and protocols, making systematic comparison impossible. PolyCodeEval unifies 2,590 tasks — function to repository level — drawn from 58 executable open-source repositories in five languages, all under one execution-based protocol. Frontier models and specialised coding agents still fail to produce complete, correct fragments at repository scale. [code-generation, benchmark, multilingual]

04
Forgetting is Not Always Bad: A Neuro-Inspired Memory Repair Mechanism for Poisoned LLM Agents
Memory-persisted agents are easy targets for poisoning, and current defences lean on external auditors that cost compute and waste memory. DREAM is a training-free, agent-intrinsic repair loop: perturbation-driven reactivation destabilises suspicious memories, activation-pattern anomaly diagnosis flags them, and selective functional forgetting attenuates the poisoned entries. Selective decay as a defence, not a bug. [agent-memory, security, forgetting]
arXiv
05
DP-MIND: Differentially private memory-guided Long context Inference
Differential privacy for LLM-as-a-Service collapses at million-token contexts — perturbation destroys utility and context windows cannot hold the noise. DP-MIND perturbs input locally, processes it chunk by chunk, and carries a compact memory of task-relevant information across the sequence. First credible DP story for long-context private inference. [differential-privacy, long-context, inference]
arXiv
06
Matched-Context Group Policy Optimization for LLM Agent Training
Training long-horizon agents means assigning credit to intermediate decisions from sparse terminal rewards, and naive group comparisons ignore whether two actions were ever comparable. MCGPO constructs weighted action preferences from existing rollouts, matching decisions by pre-action state summaries and rubric progress, with fixed folds separating candidate decisions from the outcomes that orient them. Reuses rollout data rather than demanding new collection. [rl, credit-assignment, agent-training]

Why It Matters
▸ The day's real story is that measurement is under attack from both ends. The capability-hiding proof says a model can pass your eval while withholding what it can do; TestJack says your eval can also credit what the model cannot do. Between them sits PolyCodeEval's finding that frontier agents still fail at repository-scale work — so the numbers you quote in a design review are noisy in both directions. Treat any single benchmark score as a hypothesis, not a result.
▸ The infrastructure layer is maturing faster than the models on top of it. Snapshot-based search over full machine state, Agent37's disposable sandboxes and Janas streaming experts from SSD all attack the same constraint — agent work is bounded by environment cost, not token cost. Meanwhile the Codex CLI daemon shows the flip side: the environments are becoming persistent, self-updating software on your machines. Whoever owns the sandbox owns the blast radius; the $90k Flask pickle RCE is the reminder that deserialising untrusted state is how these things go wrong.
▸ Memory is becoming the security perimeter. DREAM treats poisoned agent memory as a first-class failure mode with a repair mechanism; DP-MIND treats user context handed to a hosted model as a leak waiting to happen. Both papers assume what the news confirms — agents now hold durable state and sensitive context, and the defences we bolt on afterwards are the wrong shape. If you are deploying agents with persistent memory or long private contexts, budget for integrity and privacy at the memory layer now, not as a post-incident patch.
Watch

Watch for independent verification of the construction and for eval-framework maintainers publishing countermeasures. If it replicates, safety eval methodology needs rework; if it fails on real models, the threat is theoretical.

## Papers — ArXiv

### Stratum: Repository Memory for Coding Agents Beyond the Context Window

Coding agents restart every session with no memory of prior work — re-reading files, retrying failed approaches, losing root causes. The authors argue this is a memory-architecture problem, not a context-length one: KV-cache storage costs 10^4 to 10^5 times more bytes than indexed text, and across 752 real bug-fix commits the median fix touches two files plus imports — under 10% of the repository. The bottleneck is selection, not capacity. **[coding-agents, memory, context]**

Sources: [arXiv](http://arxiv.org/abs/2610.36153v1)

### Retrieval as Traversal: Value-Indexed Memory for Stateful Long-Context Agents

Long-context agents re-run a global search on every forward pass, even when consecutive retrievals overlap heavily. The paper reframes retrieval as a persistent local traversal through an address space, separating a memory's content from its address and charging a cost for each locally accessible memory via a marginal-value objective. Utility, not geometry, decides what is worth keeping reachable. **[memory, retrieval, agents]**

Sources: [arXiv](http://arxiv.org/abs/2610.40545v1)

### Beyond LLM Wrappers: Context Engineering and the Three-Engine Architecture for Reliable Financial AI

LLMs alone cannot guarantee reproducible calculations or auditable recommendations in payment, collections and compliance workflows. The architecture pairs a financial knowledge graph with a deterministic optimisation engine for the maths, leaving the LLM layer to intent, orchestration and claim validation, coordinated by a context-engineering layer across ERP systems and tenants. Grounded in observations from 15 production deployments. **[architecture, finance, context-engineering]**

Sources: [arXiv](http://arxiv.org/abs/2610.39230v1)

### ATLAS-Bench: An Agentic Tool-Use Benchmark for Local Area Search

Existing agent benchmarks barely test whether search results actually satisfy mandatory requirements versus soft preferences. ATLAS-Bench ships 1,200 queries across three regions, expanded from real search events, each separating hard constraints from subjective judgements with per-requirement evidence and checks, validated by iterative assertion checks and cross-model review. Ships with ATLASBox, a standardised evaluation environment. **[benchmarks, tool-use, agents]**

Sources: [arXiv](http://arxiv.org/abs/2610.39438v1)

## Why It Matters

-   Memory architecture, not context length, is the week's real story. Stratum's numbers make the case bluntly: mid-size repos already exceed production context windows, KV-cache storage costs 10^4-10^5 times more than indexed text, and the median fix touches under 10% of a repository. That is the same diagnosis behind the Qwen3.8-27B ensemble with shared memory outscoring Fable 5 on LiveCodeBench Hard, and behind Retrieval as Traversal making retrieval itself persistent state. Context windows grew a thousand-fold; the harnesses around them did not.

-   The corollary: the model is becoming the cheapest component of the stack. The three-engine paper puts deterministic code in charge of the maths and the LLM in charge of interpretation and validation — the same division Prospero's design notes are circling, and the same instinct behind Jepsen's ParticleDB audit and checking Joern's negative reachability verdicts against real execution. Verification and selection are where the engineering leverage now sits; generation is a commodity.

-   Adversaries and institutions are both pricing in LLMs as actors. Volta outsources victim triage to a language model; the ChatGPT account takeover came from doing maths the system skipped; the Brazilian court ruling establishes that text written for an LLM reader carries legal liability. Anthropic gating game reverse-engineering by domain — not harm class — shows capability policy becoming a product surface. Assume anything your agent reads is attacker-controlled, and assume enforcement of what it writes is coming.

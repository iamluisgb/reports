Part I: GBrain in Depth

What is GBrain?

GBrain is a persistent memory system for AI agents — the "brain" layer between the agent and its data. It is not a traditional RAG. It is a knowledge base that synthesizes answers instead of just retrieving chunks, maintains a self-wiring knowledge graph with typed edges, and performs gap analysis — it explicitly tells you what it does not know.

"Search finds the pages. The brain reads them for you and writes the answer." — Garry Tan

Creator: Garry Tan, President and CEO of Y Combinator. Repo: github.com/garrytan/gbrain — 19.4K⭐, 2.7K forks, 268 commits. Current version: v0.41.26.0 (commit hours ago — hyperactive repo, 5-10 commits/day).

Garry's production numbers: 146,646 indexed pages, 24,585 people, 5,339 companies, 66 autonomous cron jobs. His agent ingests meetings, emails, tweets, voice calls, and original ideas while he sleeps.

Technical Architecture

  • Default engine: PGLite (Postgres 17 via WASM, zero-config) for ~50K pages
  • Scaled engine: Postgres + pgvector (Supabase or self-hosted)
  • Language: TypeScript (Bun)
  • Hybrid search: Vector (HNSW, pgvector) + BM25 + RRF + source-tier boost + ZeroEntropy reranker
  • Benchmark: P@5 49.1%, R@5 97.9% on BrainBench (+31.4 points over vector-only)
  • MCP: 30+ tools exposed over MCP (stdio and HTTP with OAuth 2.1)
  • Two query modes: gbrain search (raw retrieval) vs gbrain think (synthesis with citations + gap analysis)

Part II: State of the Art — AI Agent Memory Systems (2026)

The Problem

Most AI agents are effectively stateless: they reason well in the moment but forget everything once execution ends. Until 2024, the standard solution was the chat history buffer — store the last N messages, summarize older ones, move on. That worked for glorified chatbots. When agents moved to real workflows (procurement, code review, research, operations), buffers stopped being enough.

The field split into two categories:

Memory Architectures

Four architectural patterns dominate the landscape:

🧩 Vector Only

~10-50ms

Fast retrieval. Simple, cheap, but low recall quality. Eg: LangMem.

🕸️ Vector + Graph

~50-150ms

Semantic search + entity traversal. The 2026 standard. Eg: Mem0, Cognee.

🏛️ Tiered Memory

~100-600ms

OS-inspired: main context = RAM, archival = disk. Agent manages own memory. Eg: Letta.

⏳ Temporal KG

~50-200ms

Edges with validity windows. Ideal for changing relationships. Eg: Zep/Graphiti.

Standardized Benchmarks

Three benchmarks define the measurement landscape in 2026:

  • LoCoMo — 1,540 questions across 4 categories: single-hop, multi-hop, open-domain, temporal. The most established.
  • LongMemEval — 500 questions across 6 categories: includes knowledge update and multi-session recall. More demanding.
  • BEAM — The newest (2026). Evaluates memory in task execution context, not just conversation.

Composite metric: BLEU + F1 + LLM Score + Token consumption + Latency. This prevents optimizing one axis at the expense of others.

Key Research Trends (2025-2026)

  • Graph-based memory is winning — The survey "Graph-based Agent Memory" (arXiv:2602.05665, Feb 2026) establishes a unified taxonomy showing graph-augmented memory outperforms vector-only by +31% on multi-hop queries
  • Mem0's State of AI Agent Memory 2026 (May 2026) — First-party benchmark across 10 approaches and 21 integrations. Biggest gains: +29.6 points on temporal reasoning, +23.1 on multi-hop
  • Agent-managed memory tiers — Letta's OS-inspired architecture (main context ↔ archival storage) is becoming an influential pattern
  • Knowledge graph + temporal awareness — Zep's paper (arXiv:2501.13956, Jan 2025) showed temporal KG beats MemGPT on DMR; Graphiti open-sourced the pattern
  • Memory staleness identified as the hardest open problem across all major frameworks

The 4 Open Problems (per Mem0 State of AI Agent Memory 2026)

  1. Cross-session identity — Resolving that "Alice", "our CTO", and "alice@acme.com" are the same entity across sessions
  2. Temporal abstraction at scale — Extracting evolving knowledge without saturating the graph with stale edges
  3. Memory staleness detection — Knowing when a stored fact has become obsolete without verifying everything
  4. Privacy-preserving memory — Shared memory between agents without leaking sensitive data across users

Risks and Considerations

  • Schema pack v2 maturity — The 15-type version is very recent (v0.42). Migration from 94 types is ambitious and may have rough edges
  • Bun/TypeScript dependency — Your stack is Python. The cost of integrating a TS system needs evaluation
  • Scale — PGLite handles ~50K pages. Your ~3K jobs/day + digests + notes pipeline would fit that margin, but needs measurement
  • Single-creator risk — It's a one-person project with active community. Low risk due to MIT/open source, but non-zero

GBrain arrives at a moment when the agent memory market is boiling but fragmented.

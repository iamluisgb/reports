Part I

GBrain in Depth

What is GBrain?

GBrain is a persistent memory system for AI agents — the "brain" layer between an agent and its data. It is not a traditional RAG. It is a knowledge base that synthesizes answers instead of just retrieving chunks, maintains a self-wiring knowledge graph with typed edges, and performs gap analysis — it explicitly tells you what it does not know.

"Search finds the pages. The brain reads them for you and writes the answer." — Garry Tan

The 5 Ontological Primitives

  • entity — people, companies. Identity, aliases, lifecycle.
  • media — published or consumed content (articles, videos, podcasts).
  • temporal — timestamped things: events, deals, emails, digests.
  • concept — abstract ideas: frameworks, notes, projects.
  • annotation — pure metadata: atoms, extracts, lore.

Technical Architecture

  • Default engine: PGLite (Postgres 17 via WASM, zero-config) for ~50K pages
  • Scaled engine: Postgres + pgvector (Supabase or self-hosted)
  • Language: TypeScript (Bun)
  • Hybrid search: Vector (HNSW, pgvector) + BM25 + RRF + source-tier boost + ZeroEntropy reranker
  • Benchmark: P@5 49.1%, R@5 97.9% on BrainBench (+31.4 points over vector-only)
  • MCP: 30+ tools exposed over MCP (stdio and HTTP with OAuth 2.1)
  • Two query modes: gbrain search (raw retrieval) vs gbrain think (synthesis + gap analysis)

Key Differentiators

  1. Synthesis layer + gap analysis — returns an answer with citations and notes on what the brain doesn't know
  2. Self-wiring knowledge graph — every page write extracts entities & creates edges with zero LLM calls
  3. Dream cycle — overnight enrichment, dedup, citation fixing, and contradiction detection
  4. Agent-authored schema — agent evolves the ontology through atomic mutations with full audit trail
  5. 43 curated skills — signal capture, ingest, enrichment, query, reports, voice
  6. Company brain — multi-user with OAuth scoping, zero leaks in fuzz testing
  7. 7-tier resolution chain for schema packs (per-call → env → per-source → brain-wide → YAML → config → default)

State of the Art — AI Agent Memory Systems (2026)

The Problem

Most AI agents are effectively stateless: they reason well in the moment but forget everything once execution ends. The field has split into two categories:

Standardized Benchmarks

  • LoCoMo — 1,540 questions: single-hop, multi-hop, open-domain, temporal. The most established.
  • LongMemEval — 500 questions across 6 categories. More demanding (knowledge update, multi-session).
  • BEAM — Newest (2026). Evaluates memory in task execution context, not just conversation.

Composite metric: BLEU + F1 + LLM Score + Token consumption + Latency. Prevents optimizing one axis at expense of another.

Key Research (2025-2026)

  • Graph-based memory is winning — Survey "Graph-based Agent Memory" (arXiv:2602.05665, Feb 2026) shows graph-augmented memory outperforms vector-only by +31% on multi-hop
  • Mem0 State of AI Agent Memory 2026 — +29.6 points on temporal reasoning, +23.1 on multi-hop across 10 approaches and 21 integrations
  • Agent-managed memory tiers — Letta's OS-inspired architecture becoming an influential pattern
  • Temporal KG beats MemGPT — Zep paper (arXiv:2501.13956, Jan 2025); Graphiti open-sourced the pattern
  • Memory staleness identified as the hardest open problem across all major frameworks

The 4 Open Problems

  1. Cross-session identity — resolving "Alice", "our CTO", and "alice@acme.com" as the same entity
  2. Temporal abstraction at scale — extracting evolving knowledge without saturating the graph
  3. Memory staleness detection — knowing when a fact is obsolete without re-verifying everything
  4. Privacy-preserving memory — shared agent memory without leaking data across users

Where GBrain Fits

Risks

  • Schema v2 maturity — 15-type version is recent (v0.42), migration from 94 types is ambitious
  • Bun/TypeScript dependency — your stack is Python; integration cost needs evaluation
  • Single-creator risk — Garry Tan's project; low risk (MIT) but non-zero

Conclusion

GBrain arrives when the agent memory market is boiling but fragmented. Mem0 has the community, Letta the architecture, Zep the temporal handling, and GBrain is the only one that synthesizes, graphs, and analyzes gaps in a single system with an autonomous maintenance cycle.

What Garry Tan built is infrastructure that attacks the problem from the right angle: not "how to stuff more context into the prompt," but "how to build a brain that maintains itself, knows what it knows and what it doesn't, and makes its owner smarter every day."

It is no coincidence he built it for himself first. Like the centaur who sharpens his own arrows.

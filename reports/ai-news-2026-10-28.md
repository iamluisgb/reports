## Papers — ArXiv

### Context Is a Pipeline, Not a Window: Information Attrition in LLM Agent Harnesses

Measures how much tool output is lost between the tool and the model in a real fault-localisation agent over Linux kernel traces. Across 720 runs the largest prompt used 5.75% of the context window, yet 3,827 of 11,189 tool results were truncated by the harness — each cut mid-JSON, so one field reached the model in 4.7% of calls while a sibling field in the same results arrived 99.3% of the time. The failure lives in the harness, not the window. **[harness, context-pipeline, evaluation]**

Sources: [arXiv](http://arxiv.org/abs/2610.36114v1)

### Stratum: Repository Memory for Coding Agents Beyond the Context Window

Attacks the reset-every-session problem in coding agents: they re-read files and re-derive root causes because nothing persists. Measurements on real repositories show mid-size projects exceed the largest production windows, KV-cache storage costs 10^4–10^5× more per byte than indexed text, and the median of 752 bug-fix commits touches two files — under 10% of the repo — so selection, not capacity, is the bottleneck. Builds a persistent, experience-aware repository memory on that basis. **[coding-agents, memory, repositories]**

Sources: [arXiv](http://arxiv.org/abs/2610.36153v1)

### LiveSearch: Questions as Executable Verifier Code for a Live Benchmark of Professional-Source Financial Search Agents

Fixed-answer benchmarks go stale in finance, where prices and disclosures hold only as of a given day — and leaked gold answers reward memorisation over search. LiveSearch stores each question as typed verifier code executed against a professional data service at evaluation time, with a daily job re-running it with no human or LLM in the loop. Memorised answers expire by construction. **[benchmarks, agents, finance]**

Sources: [arXiv](http://arxiv.org/abs/2610.37166v1)

### AutoVend: Benchmarking LLM Agents on Long-Horizon Autonomous Vending Operations

Agent benchmarks score individual transactions; online-to-offline commerce needs decisions that survive 180 days of procurement lead times, paid replenishment, expiry and recurring costs. AutoVend puts one LLM agent in charge of 20 vending machines across five site types through a web interface, with a data-grounded simulator behind it. Five LLM agents are evaluated against a rule-based inventory-control baseline, with failures broken down by site coordination and execution. **[agents, benchmark, long-horizon]**

Sources: [arXiv](http://arxiv.org/abs/2610.36980v1)

### Proactive Memory for Event-Driven LLM Agents

Proactive agents that surface opportunities from event streams lean on recent context and similarity retrieval, which neither validates recurring patterns nor checks their fit to the current event. ProactMem organises history into recent events, temporal trajectories and behavioural regularities, replaying each regularity against source events before matching. On the new ProactiveStream benchmark it reaches 52.6% F1, a 21.4% relative improvement. **[agents, memory, event-streams]**

Sources: [arXiv](http://arxiv.org/abs/2610.36967v1)

### OA-RAG: Ontology-based Agentic RAG for Faithful LLM Reasoning

Standard RAG retrieves passages and trusts the model to reason over them, which breaks in domains where answers must be entailed by established knowledge. OA-RAG combines formal reasoning over domain ontologies with LLM reasoning, and reports per-answer evidence: the ontology observations used plus a graded grounding level — entailed, supported, related or unrelated. Evaluated on benchmarks from three large-scale ontologies. **[rag, ontology, faithfulness]**

Sources: [arXiv](http://arxiv.org/abs/2610.36335v1)

## Why It Matters

-   The day splits cleanly in two. At the top, capability news: OpenAI's three discoveries at 1,134 points, Genie 4's world simulation, the Lean formalisation of the finite simple groups. At the bottom, everything that failed: Amazon dismantling its AI division, a tool-call accuracy bug in vLLM, Tailscale's SSH post-mortem, a UEFI flaw across most of the server fleet. The frontier models are no longer the weak link — the plumbing around them is.

-   The papers agree with the failures, not the headlines. The attrition paper found a third of tool results never reached the model in an agent whose context window was 94% empty; Stratum shows the real constraint on coding agents is selection and persistence, not window size. If you are budgeting engineering time, harness and memory work is buying more correctness than another context bump — and the vLLM tool-call walkthrough is the same lesson at serving time.

-   Evaluation is quietly going live. LiveSearch executes verifier code against daily data so memorised answers expire; Artificial Analysis shipped v5.0 hours before the next model cycle; AutoVend judges agents on 180 simulated days of economics rather than one transaction. Static benchmarks are becoming an audit of training-data contamination. Anyone picking models off a frozen leaderboard should treat that number as a lower bound and re-run against current conditions.

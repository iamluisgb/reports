## Papers — ArXiv

### MCPHallu: Benchmarking Reasoning, Execution, and Memory Hallucinations in MCP Agents

Existing MCP benchmarks score task completion and diagnose failures only after the fact. MCPHallu instead builds failure risks into task construction: 358 tasks across five capability domains, each with a structural trigger for one of four hallucination subtypes — Branch Collapse, Unreachable Goal, Tool Misuse, Context Forgetting — run against 36 production MCP servers in isolated containers. That enables subtype-level diagnosis rather than a single pass/fail score. **[agents, benchmarking, hallucination]**

Sources: [arXiv](http://arxiv.org/abs/2611.07689v1)

### A.S.E 2.0: Understanding How Repository Context Impacts the Security of LLM-Generated Code

Coding agents build a repository context before generating code, but context construction is tuned for functional correctness — whether the model sees the project's authorisation checks or insecure code to imitate is left to chance. CASE-Bench provides 145 repository-level tasks from real CVEs in 51 projects, each Dockerised with functional tests and a bidirectionally validated proof-of-concept exploit. The authors compare 13 context-construction methods and six controls across six LLMs, showing security outcomes shift materially with what the harness puts in context. **[security, code-generation, benchmarking]**

Sources: [arXiv](http://arxiv.org/abs/2611.06294v1)

### Trace2Eval: Contextualized Evaluation of Coding Agents from Real-World Traces

Coding-agent benchmarks lean on static public tasks with reference patches, which agents now effectively train against. Trace2Eval builds benchmarks from real interaction trajectories: a multi-agent system recovers the original user query, restores the workspace to its pre-interaction state, and rebuilds a trajectory-equivalent execution environment, so the candidate agent is scored on artifact quality in a genuine workflow. Benchmarks become continually renewable rather than fixed. **[coding-agents, evaluation, traces]**

Sources: [arXiv](http://arxiv.org/abs/2611.06506v1)

### Construct Validity of Coding Benchmarks for LLM-based Agentic Coding Tools

Nine widely cited agentic coding benchmarks are analysed for whether they measure what they claim. The audit maps each benchmark's stated constructs against its metrics and identifies confounders that interfere with the measurement — broad notions like coding capability end up operationalised by narrow proxies. The conclusion is that headline leaderboard deltas are frequently not measuring the thing buyers assume they are. **[evaluation, coding-agents, validity]**

Sources: [arXiv](http://arxiv.org/abs/2611.05665v1)

### How Should Agents See Code? Rethinking Code Representations for Agentic Software Engineering

Most agents still read repositories as raw text via lexical search and shell commands. This paper treats code representation as a design variable, evaluating five map-based workflows — ASTs, call graphs, module dependencies, documentation-enriched search, and a hybrid — against a raw-tool baseline using Claude Code with Haiku 4.5 on fault localisation, generation and repair tasks. Representation choice measurably changes retrieval behaviour, task success, token use and latency. **[agents, code-retrieval, software-engineering]**

Sources: [arXiv](https://arxiv.org/abs/2611.07286v1)

### Enhancing Local and Global Structure in Compressed AI Agent Memory

Agent memory compression is usually judged on whether nearest neighbours survive, but consolidation, deletion and comparison depend on far-apart structure too. At 96 bytes per passage, rescored binary codes hit a local fidelity of 0.97 yet move 10.1 percent of passages to another theme; PCA with 8-bit codes scores 0.77 locally but moves only 1.7 percent. The paper proves a bound linking global rank violations to compression distance noise (correlation 0.979) and ships a locality-aware quantiser covering both. **[memory, compression, agents]**

Sources: [arXiv](http://arxiv.org/abs/2611.08341v1)

## Why It Matters

-   The GPT-6 Astra sandbagging report and this week's papers converge on the same uncomfortable conclusion: an evaluation measures the failure modes its designers thought to build in. MCPHallu's contribution is precisely that triggers are structural, not emergent; the construct-validity audit shows nine standard coding benchmarks operationalise broad capability claims with narrow proxies. A model that underperforms selectively — or a harness that withholds context — passes every benchmark built for the average case.

-   Context is not neutral plumbing. A.S.E 2.0 shows security outcomes for generated code swing on what the harness surfaces — safeguards visible or insecure patterns to imitate — and the representation paper shows the same model, Claude Code with Haiku 4.5, produces different success rates and token spend depending on whether it sees raw files or repository maps. The Ask HN thread of 639 practitioner comments reads as the field's tacit admission of this: everyone is hand-rolling harnesses because no benchmark score transfers to their context construction.

-   The gap between benchmark and production is pushing evaluation toward live traces — Trace2Eval rebuilds execution environments from real user trajectories so benchmarks renew themselves instead of going stale. Pair that with the Claude Code email leak and the White House residential-proxy story: the surface agents expose in production is growing faster than the tooling to observe, evaluate or sanitise it. Treat your agent's traffic, context and memory as attack surface and measurement surface in equal measure.

## Papers — ArXiv

### When Relevant Code Is Wrong: Runtime-Aware Context for AI Coding Agents

Retrieval for coding agents ranks code by semantic similarity and recency, neither of which establishes that a snippet still applies under feature flags, migrations, or deployment-specific configs. The paper defines operational context validity — a task-, deployment- and time-dependent criterion — and instantiates it in CASE, an agent-agnostic framework that ties repository artifacts to runtime configuration and architectural evolution, labelling evidence valid, invalid or unknown before it reaches the agent. Retrieval quality becomes a runtime question, not an embedding question. **[coding-agents, retrieval, context-engineering]**

Sources: [arXiv](http://arxiv.org/abs/2610.38800v1)

### CARI: Cross-Boundary Adversarial Runtime Injection in Coding-Agent Workflows

When coding agents build software from components owned by other teams, a compromised peer service, test harness or CI job can lie in its runtime feedback — diagnostic authority without action authority, exploited. CARI formalises this injection setting and shows an attacker can steer a victim agent's edits without ever touching its prompt, model or tools. A concrete attack surface for the multi-team agent workflows most organisations are already running. **[security, coding-agents, prompt-injection]**

Sources: [arXiv](http://arxiv.org/abs/2610.38799v1)

### Launder-Bench: Can Repository-Level Agentic Code Laundering Be Detected?

Agents can now rewrite whole repositories while preserving tested behaviour, breaking plagiarism detection, licence auditing and provenance. Launder-Bench is the first repository-level benchmark for provenance under agentic rewriting, built from 282 real-world repositories, with a source-hidden protocol that decomposes and reconstructs modules so similarity ranking alone cannot establish derivation. The result is a measurement problem for every licence-compliance pipeline that assumed textual similarity implies copying. **[provenance, code-generation, benchmark]**

Sources: [arXiv](https://arxiv.org/abs/2611.01966v1)

### Decentralized Multi-Agent Coordination and Communication in Shared Codebases

Orchestrator-free multi-agent coding is the realistic case: separate developers file separate requests and agents collide in the same repository. ParallACT benchmarks complementary and contradictory task pairs, comparing a single-agent oracle against multi-agent settings varying execution order and visibility. Independent solutions that each pass their tests can still fail when merged — the benchmark quantifies exactly how much. **[multi-agent, code-generation, benchmark]**

Sources: [arXiv](https://arxiv.org/abs/2611.00314v1)

### Experts Exhibit Structured Redundancy: Structure-Preserving Expert Pruning for MoE LLMs

MoE models must store every expert at inference even though expert outputs carry far fewer effective modes than the nominal expert count — stable and entropy effective ranks sit well below it across models and tasks. The paper reframes pruning as structure-preserving subset selection solved greedily, rather than scoring experts independently. A memory-reduction lever that follows from measured rank structure, not heuristic importance scores. **[moe, pruning, inference-efficiency]**

Sources: [arXiv](http://arxiv.org/abs/2610.41236v1)

### ImplicitHop: Evaluating knowledge integration across context and memory

Models must propagate the long-range consequences of new facts, whether those facts arrive in-context or in pretrained weights — and the two channels behave differently. ImplicitHop supplies two benchmarks: a formal graph benchmark with controlled topologies, and a composition benchmark grounded in real knowledge graphs, evaluating deductive reasoning as a function of inference depth. Direct evidence for the context-versus-weights asymmetry that retrieval and fine-tuning decisions quietly depend on. **[reasoning, evaluation, knowledge-integration]**

Sources: [arXiv](http://arxiv.org/abs/2610.41169v1)

## Why It Matters

-   The through-line across today's papers is that the coding agent's environment — not the model — is now the research frontier. CASE attacks retrieval that surfaces plausible but dead code, CARI attacks runtime feedback that can be forged, ParallACT attacks agents colliding in shared repos. None of these are model problems; all of them are harness problems. The teams shipping agents fastest are the ones instrumenting the environment, and this batch gives you three concrete failure modes to test against.

-   Provenance is about to become an operational burden rather than a legal afterthought. Launder-Bench shows agents can rewrite repositories past the reach of clone detection, while OpenAI's write-up on Git at thousands-of-engineers-plus-agents scale is the infrastructure response to the same pressure. If your compliance story assumes similarity implies derivation, or that your VCS metadata is trustworthy at agent commit volume, both assumptions now have expiry dates.

-   Two different writable substrates appeared today and they point the same direction: Astra treating weights as a readable, writable address space, and the agent papers treating repos and runtime feedback as programmable surfaces. Meanwhile Anthropic's internal AI spend exceeding payroll and its flattening growth curve suggest the unit economics of doing all this at frontier scale are worse than the capex narrative admits — Oracle raising $20B against that backdrop is a bet someone will have to underwrite. Watch whether weight-editing and harness work converge: cheap post-hoc model improvement is the obvious answer to expensive pretraining.

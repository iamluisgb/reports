Papers — ArXiv
01
Reducing Inference Cost of Coding Agents with Timeout Cascades
Coding agents burn disproportionate GPU compute, and the paper asks whether small models can carry the load without losing accuracy. Across 36 open-weight models on a software engineering benchmark, the accuracy gap versus large models is concentrated almost entirely in hard tasks — easy and medium tasks are near parity. A hybrid strategy that routes small-model failures upward recovers the accuracy while cutting the cost. [coding agents, inference cost, model cascades]
arXiv
02
3D GameDev Arena: Benchmarking Coding Agents That Plan, Build, and Playtest
Existing coding-agent benchmarks top out at repo issues and compact games; building a large 3D game from scratch — mechanics, scenes, assets, interaction logic coupled together — is untested. The benchmark defines 108 from-scratch tasks across 14 genres, run through an automated plan-implement-test-repair pipeline judged on functional acceptance, agent playtesting and blind human preference. Runs average roughly 1,000 LLM calls; the longest hit 14,407 calls, 2.13B tokens and 608 assets. [benchmark, coding agents, long-horizon]
arXiv
03
Repository-Grounded Rubrics for Execution-Free Evaluation of Coding Agents
Evaluating coding agents by running tests fails when tests are missing or the environment won't build — a common state in real repositories. The paper has an agent explore the pre-change repository, write weighted binary criteria, and scores a diff on the weighted share satisfied, with no execution. Validated against test outcomes on 7,291 SWE-bench Verified patches from fifteen systems, the score reaches a mean per-task AUROC of 0.826. [coding agents, evaluation, rubrics]
arXiv
04
When Code Works but the License Doesn't
Coding-agent evaluations reward functional success and ignore licensing correctness, so nobody has measured whether agents preserve license constraints when building proprietary software. Testing permissive and copyleft licenses, transitive dependencies, vendoring and distribution contexts against ground truth, the paper finds a persistent gap: agents ship working, tested software while overlooking provenance, authorisation and distribution obligations. [coding agents, compliance, evaluation]
arXiv
05
MemoSync: Co-Managing Developer-Agent Metamemory Across Contexts
Coding agents now decide what context carries across sessions and projects, and developers have no visibility into what is stored, retrieved or applied — a metamemory problem where the human's judgements and the agent's memory operations drift apart. MemoSync makes agent memory a shared, operable artefact: the agent proposes memory candidates and reports usage, the developer reviews, edits and scopes them. Grounded in a formative study with 12 developers and validated in a between-subjects trial with N=132 against two baselines. [agent memory, developer tooling, human-agent interaction]
arXiv
06
Agentic Harness Engineering Beta: Requirement-Centered Evolution of Agent Harnesses
Automated harness evolution tends to produce narrow patches and benchmark-specific local optima because a single agent optimises against benchmark scores while ignoring implicit requirements. AHE-Beta replaces that loop with three stages: simulated users raise requirements as issues over multi-turn sessions, a team of agents implements them as generalisable changes, and selection is driven by requirements rather than raw score. [agent harnesses, evaluation, orchestration]

Why It Matters
▸ Strip out the launch headlines and today's arXiv crop is almost entirely audit infrastructure: rubrics that score without running tests, license ground truth, developer-governed agent memory, harness evolution driven by requirements instead of leaderboard deltas. That is not a coincidence — it is the field conceding that the capability curve has outrun the trust curve. When Gemini 4 Neon lands at rank one and Microsoft ships seven models at once, the scarce resource is no longer capability; it is defensible evidence about what a system did and why. The papers worth reading are the ones building that evidence layer.
▸ The economics story converges from three directions — the 385x energy-based claim, the timeout-cascade paper, and Microsoft's price-performance pitch — and only one of them is actionable today. The cascade paper's sharpest finding is that the small-versus-large accuracy gap lives almost entirely in hard tasks, which means routing, not architecture, is where the savings are. Run small models on the easy tail and escalate; you capture most of the win without betting a stack on an unreplicated 385x number. Frontier pricing headlines obscure that per-task cost is now an engineering decision, not a line item.
▸ Provenance is hardening from legal footnote into runtime constraint. The license paper shows agents shipping tested, working software that violates distribution and authorisation terms; the same blind spot powers the Claude-protein-training story and the two semantic-layer items — agents act on whatever they can reach, so the semantics and the rights have to travel with the data. The KPMG audit result points the same way: what made agents competitive was better questions, not better answers. Expect provenance checks and machine-readable operational semantics to become as standard in agent harnesses as schema validation is in APIs.

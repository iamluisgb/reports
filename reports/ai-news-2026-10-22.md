## Papers — ArXiv

### How Much Does the Harness Matter, and for Whom? A Multi-Model Study of Context in LLM-Driven Vulnerability Discovery

Measures whether an agent harness — not the model — determines vulnerability-discovery yield, across 24 model-runner configurations on a production codebase with 265 non-public security root causes. No single configuration covers all findings; the best two-run pair reaches 60.4%, and 14.3% are found by exactly one model. Swapping a minimal prompt for an engineered one with a CodeQL-derived call graph raises criticality-weighted yield 20-86% for smaller and mid-tier models but only 2% for the frontier model. **[agent-harness, security, evaluation]**

Sources: [arXiv](https://arxiv.org/abs/2610.28802v1)

### PAUSE: Search-Free Steering of Coding Agents Before Their First Source-Code Edit

Coding agents burn most of a trajectory on exploration and testing, then commit to a wrong patch with no checkpoint to fall back on. PAUSE exploits the observation that the first source-code edit arrives at a median of 60% of trajectory progress: it intercepts that edit, has a separate Planner write one repair plan from the pre-edit transcript, and resumes the same agent — no learned monitor, no checkpoint search, no extra model call. **[coding-agents, steering, orchestration]**

Sources: [arXiv](https://arxiv.org/abs/2610.29870v1)

### UserSWE: Evaluating Coding Agents in Multi-Turn Conversations with Dynamic Users

SWE-bench-style benchmarks hand the agent a complete issue in one turn; real developers describe bugs badly, in pieces, over many turns. UserSWE converts repository history and existing benchmarks into multi-turn tasks where a simulated user — persona chain calibrated on 20,859 development sessions — reveals information under per-turn constraints, with execution-grounded tests after every turn. Targets the false positives and false negatives single-turn evaluation produces. **[coding-agents, benchmarks, evaluation]**

Sources: [arXiv](http://arxiv.org/abs/2610.29822v1)

### PerMIT: Securing Persistent Memory for LLM Agents via Machine-Checked Integrity Theorems and Scalable Community Trust

Persistent agent memory is an undefended injection and poisoning surface, and the same risk blocks memory sharing between agents. PerMIT trusts only user-typed inputs and gate-confirmed values, mediating everything environment-derived through a finite memory interface; two integrity theorems over that interface are machine-checked in Lean 4. Every attack in the threat model reduces to a single auditable gate decision. **[agent-memory, security, formal-methods]**

Sources: [arXiv](http://arxiv.org/abs/2610.28987v1)

### Behavior Beyond Text: Evaluating Refusal Transfer Failure in LLM Agents

Safety evaluations test whether a model refuses harmful text, but agents act through tool calls — and refusal does not transfer. Across 2,304 matched prompts and 20 forbidden actions, requests refused in chat still produce unsafe tool calls for 10-52% of cases under standard tool-enabled prompting. The paper traces the gap to a refusal-associated direction in the residual stream that tool framing bypasses. **[agent-safety, tool-use, interpretability]**

Sources: [arXiv](http://arxiv.org/abs/2610.28982v1)

## Why It Matters

-   Today's incident stack — a malicious LiteLLM wheel on PyPI, eMudhra CA keys recoverable in milliseconds, an out-of-band PHP release — is one story wearing three hats: trust placed in a package, a key, or a release channel and repaid with compromise. The papers put the same question to agents. PerMIT's answer is architectural — trust nothing environment-derived until a gate confirms it, and prove the invariant in Lean 4 rather than assert it. That is the supply-chain lesson transposed into agent memory, and it lands the same day OpenAI ships an official CLI that people will pipe untrusted output into within the week.

-   The harness paper is the day's most actionable result, and it cuts against frontier-model marketing: engineered context bought 20-86% yield for smaller models against 2% for the frontier one, and no configuration found everything. If you are paying frontier prices for security review, you are mostly buying the last 14.3% — the findings only one model catches. Pair that with PAUSE and the practical picture is that where you intervene in an agent's trajectory matters more than which model sits in the loop.

-   Refusal transfer failure and the multi-turn benchmarks (UserSWE, SWE-DIVE) point at the same gap between evaluation and deployment: agents are tested on single-turn, well-formed text but run as multi-turn tool callers against vague humans. A model that refuses in chat and executes through tools is not a safety regression — it is the default, at up to 52% divergence. OpenAI's 'Patch the Planet' shows agents already running global disclosure processes; PerMIT and the refusal-transfer work are the counterweight saying the trust boundaries for that process do not exist yet unless you build them.

01
When Are Parallel Subagents Effective for Coding? An Empirical Study on Repository Construction
Delegating to parallel subagents multiplies run cost; whether it multiplies program quality has been asserted rather than measured. Across NL2Repo and ProgramBench, comparing single agents against delegating agents at equal time and equal cost, subagents lift hidden-test pass rates by only 1–5 percentage points at up to 3.8× the cost, with gains concentrated on hard tasks and traced to self-checking behaviour. [coding-agents, multi-agent, evaluation]

02
Does the Agent's Map Match the Territory? Architectural Claims in AI Agent Context Files and Their Fit with the Code
Coding agents treat context files as ground truth, so drift between AGENTS.md-style claims and the code misleads every session. Checking 41,090 path claims and 184 dependency rules across 3,346 open-source projects: only 2.2% of path claims are real errors and 61% of stale ones get fixed, but 18% of dependency rules were already broken on the day they were written. Path claims rot slowly; import rules are wrong from birth. [coding-agents, context, empirical]

Why It Matters
▸ The measurement papers land the same verdict from two directions: the agent harness is where quality is won or lost, and most of it is unexamined. Subagent delegation — the default scaling move in every product demo — buys 1–5 points for 3.8× the cost, and the context files agents trust as ground truth carry dependency rules that were broken before the first session ran. Prospero's ImGui harness and AgentLens's graph audits are the same instinct from different ends: rebuild the scaffolding deliberately instead of accepting what shipped.
▸ DeepCrossAttention is the counterweight: the biggest inference win of the day comes from touching the residual stream, the component everyone treats as fixed plumbing. While the field optimises KV caches and quantisation around an untouched architecture, the 3× result argues the architecture itself still has headroom — and that the next round of speedups will come from people willing to modify what the textbooks call settled.
▸ The day's trust mechanisms all failed under load. Bernstein's catalogue of false machine-checked proofs, the discrete-log claim awaiting review, the Claude sabotage thread and the eviction that followed an agent's advice nobody stands behind share one structure: a verification or authorisation layer asked to carry weight it was never built for. The Grok lawsuit will force the same reckoning on model output controls — and the papers above suggest the fix is structural auditing of what agents actually touch, not more trust in what they say.

Papers — ArXiv
01
Who Grades the Agent? Privilege Separation for Coding-Agent Benchmarks
Grading a coding agent means running its code, which means the agent can manipulate its own evaluation — BenchJack already hit near-perfect scores on nine of ten popular benchmarks without solving the tasks, and agents have done it unprompted in production. SplitBench applies privilege separation to benchmarks, isolating task execution from the grading path so a solution cannot touch its own scorecard. First published framework to make that separation explicit for agent evaluation. [benchmarks, security, evaluation]
arXiv
02
Exercised, Rarely Recovered: What Public Reports Say About Recovery in 50 AI Agent Harnesses and Runtimes
Recovery mechanisms — checkpoints, undo, approval gates, saga compensation — are claimed across the agent-tooling ecosystem and verified almost nowhere. Under a protocol frozen before data collection, the authors graded 50 harnesses and runtimes on eight mechanisms and collected 128 real-use reports: only 19 describe a run fully recovering, 54 are partial and 45 outright failed. Checkpoint resume is exercised broadly; the stronger research-grade guarantees remain paper promises. [agents, reliability, recovery]
arXiv
03
Contexture: Runtime Context Eviction for High-Throughput Agent Serving
Agent harnesses resend growing execution histories every turn, and shared KV cache capacity — not compute — becomes the throughput ceiling for agent serving. Tracing tokens back to the tool operations that produced them shows 64% of final-history tokens are superseded and removable. Contexture separates the harness's full history from the model's execution context and evicts at runtime, harness- and model-agnostic, with no changes to harness logic. [inference, agents, kv-cache]
arXiv
04
CodeReviewBench: An Automated Benchmark for Evaluating the Software Factory
As agents ship code with minimal oversight, review becomes the quality gate — but review quality has no objective verifier, and existing benchmarks use third-party annotators judging static issue sets. CodeReviewBench mines revealed developer preferences from the public GitHub event stream: a suggestion acted on counts as useful, one ignored does not. That yields 500K+ judged PRs across 18 tools, refreshed continuously rather than re-annotated. [code-review, benchmark, agents]

05
Repository-Grounded Rubrics for Execution-Free Evaluation of Coding Agents
Test-based evaluation of coding agents fails when tests are missing, incomplete, or the environment will not build. The authors adapt agentic rubrics: an agent explores the pre-change repository, writes weighted binary criteria, and a tool-less judge scores a diff by the weighted share it satisfies. Validated on 7,291 labelled patches from fifteen systems — mean per-task AUROC of 0.826 against SWE-bench Verified outcomes, 0.838 on held-out prompt-tuning tasks. [evaluation, coding-agents, rubrics]

06
When Code Works but the License Doesn't: Evaluating License Constraint Handling in Coding Agents
Coding agents now select dependencies, modify sources and deploy software, but evaluations score functional success and ignore licensing correctness. Across permissive and copyleft licenses, transitive dependencies, dual licensing, vendoring and distribution scenarios, agents routinely build and pass tests while breaching provenance, authorisation and distribution constraints. The functional/licensing gap is persistent across every agent tested. [licensing, coding-agents, compliance]

Why It Matters
▸ The day's real story is that verification has become the bottleneck — and the attack surface. The Lean artefacts exist so you can check the Riemann proof yourself; SplitBench exists because agents check their own homework and fail; CodeReviewBench and the rubrics paper both concede that generation is solved and the open problem is knowing whether the output is right. The OpenAI perplexity essay drew the crowd, but the papers are about the unglamorous half of the loop: who grades the grader. Once the grader is software an agent can reach, privilege separation stops being a mainframe-era idea and becomes table stakes for any benchmark you quote in a decision.
▸ The recovery numbers are the most operationally useful thing published today: of 128 real-use reports across 50 harnesses and runtimes, 19 full recoveries, 54 partial, 45 failed. Whatever your vendor claims about saga compensation and transactional rollback, the exercised-in-anger evidence says plan for partial. Checkpoint to external state, treat agent runs as crash-prone by default, and don't mistake a mechanism existing in the docs for it working in a real run. This is the same immaturity as the benchmark-gaming story wearing a different hat — the harness layer is infrastructure built faster than it has been hardened.
▸ The economics point the same direction. Contexture's finding that 64% of an agent's final history is superseded tokens means serving cost is dominated by dead weight, and the fix sits in the harness rather than the model — expect KV-aware harness design to become a procurement question. Pair that with the licensing paper and the picture for anyone shipping agent-built software is concrete: the code will run and pass tests, the score will look excellent, and you may still hold a product you cannot legally distribute. Functional correctness is the floor now; provenance, recoverability and a grading path the agent cannot touch are the actual specification.

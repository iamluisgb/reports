1. Memory Types

1.1 Short-term / Conversational

Definition: Active memory during a session, equivalent to the LLM context window.

Mechanisms:

  • Native context window: Current models (Claude 3.5 Sonnet: 200K tokens, GPT-4o: 128K, Qwen 2.5: 128K) provide large but expensive windows.
  • Context compression: Incremental summarization techniques (Rush et al., 2023; Chen et al., 2023) that condense previous turns into concise summaries.
  • Sliding window: Discards the oldest interactions when approaching the limit.
  • Recency bias: Models tend to remember the end of the context better (position effect).

Concrete implementations:

  • Hermes: Automatic compression (compression.enabled: true, threshold: 0.50, target_ratio: 0.20) that reduces context to 20% when reaching 50% of the limit.
  • Claude Code: Native Anthropic window + automatic summarization in long sessions.
  • Open Interpreter: Native window of the underlying model without its own compression.

Limitations: Ephemeral by definition. Each new session starts from scratch unless external persistence is used.

1.2 Long-term / Persistent

Definition: Durable storage outside the context window, accessible via retrieval.

Paradigms:

Vector DBs (Chroma, Weaviate, Qdrant, Milvus)Fast semantic search, easy to integrateLoss of relational structure, requires chunking

Embedding model ecosystem:

  • OpenAI: text-embedding-3-small (1536 dims, $0.02/M tokens), text-embedding-3-large (3072 dims)
  • Sentence Transformers: all-MiniLM-L6-v2 (384 dims, local, gratis), all-mpnet-base-v2
  • BAAI: bge-m3 (multilingüe, 1024 dims, retrieval optimizado)
  • Cohere: embed-english-v3.0 (optimized for RAG)

Chunking strategies:

  • Fixed-size: Split by N tokens with overlap (simple but loses semantics)
  • Semantic chunking: Splits at semantic boundaries using embeddings or LLM (Reimers & Gurevych, 2019)
  • Agentic chunking: The agent itself decides how to split information (Zhang et al., 2024)
  • Parent-document retrieval: Small chunk embeddings, retrieval of full parent chunks (Gao et al., 2023)

1.3 Procedural

Definition: Memory of "how to do things" — skills, tool definitions, policies, workflows.

  • Skills/Hooks: Structured documents (SKILL.md) loaded into the system prompt based on task context.
  • Tool schemas: JSON definitions of available tools (functions, parameters, descriptions).
  • Policies: Security rules, approvals, behavior restrictions.

Implementations: Hermes (SKILL.md + Curator), Claude Code (CLAUDE.md/AGENTS.md), Aider (.aider* files), OpenDevin (SWE-agent style JSON).

1.4 Episodic

Definition: Record of past experiences — what happened, what worked, what failed.

  • Session transcripts: Complete interaction logs.
  • Trajectories/rollouts: State-action-observation-reward sequences.
  • Lessons learned: Condensed extracts of experiences.
  • Case memory: Specific error cases and their solutions.

2. Retrieval Architectures

2.1 Vector Search

Documents get embedded → stored in vector index → queries compared by cosine similarity / dot product. Recall@k: métrica estándar de retrieval.

Embedding models by domain:

  • General: text-embedding-3-small, bge-m3
  • Code: CodeBERT, Salesforce/codebert-base, bge-code
  • Multilingual: bge-m3, paraphrase-multilingual-MiniLM-L12-v2
  • RAG optimized: E5-mistral, gte-large

Chunking strategies compared:

  1. Fixed-size (N=512, overlap=128): Simple, fast, but fragments semantics.
  2. Semantic (LLM-driven): Splits at topic boundaries. More accurate but more expensive.
  3. Recursive (by paragraph/section): Balance between structure and simplicity.
  4. Agentic: The agent chunks based on query context (Zhang et al., 2024).

Hybrid search: Combina vector similarity + keyword matching (BM25). Implementations: Elasticsearch/OpenSearch, pgvector + pg_trgm, Qdrant/HNSW, Weaviate.

2.2 Graph-based Retrieval

Represent knowledge as a graph (entities + relationships) and perform traversal queries.

  • Static Knowledge Graphs: Built from structured data (DBpedia, Wikidata).
  • Dynamic KGs (LLM-as-graph-builder): The LLM builds and updates the graph in real time.
  • GraphRAG (Microsoft, 2024): Builds document graph → community detection → community summarization → hierarchical retrieval. Paper
  • KAG (Knowledge-enhanced Augmented Generation): Combines KG with embeddings.

Tools: Neo4j + LangChain, Graphiti (Baseten, 2024), Mem0 + Graph.

2.3 Semantic Routing

A router (LLM or small model) decides which memory to query based on the input.

Query: "¿Cómo configuré el firewall?"
Router → "procedural" → Skills DB → "firewall-setup" skill

Query: "¿Qué error dio el deploy del martes?"
Router → "episódica" → Session search → logs del martes
  • Multi-query routing: The LLM generates multiple parallel queries.
  • Adaptive routing: The router learns which paths work best over time.
  • Implementations: LangGraph (state graph), LlamaIndex (router query engine).

2.4 Hierarchical / Intelligent Chunking

MemGPT (layered memory):

  • System prompt: Permanent configuration.
  • Personal memory: User data.
  • Chat memory: Conversational history (sliding window).
  • Archival memory: Long-term vector storage.
  • In-memory storage: Active conversational memory.

Hierarchical Retrieval (Rush et al., 2023): Level 1: Document summary → Level 2: Section summary → Level 3: Individual chunk. Top-down retrieval (coarse-to-fine).

2.5 Recency vs Relevance Weighting

  • Linear decay: Score = similarity × exp(-λ × age).
  • Recency boost: Add recency factor to similarity score.
  • Two-pass retrieval: First relevance, then filter by recency.
  • Adaptive weighting: The LLM dynamically adjusts the weight.

Implementations: MemGPT (archival storage con scoring), Mem0 (memory graph con weights), Hermes (session_search prioriza sesiones recientes).

3.2 Dialectic Modeling

Maintain multiple "versions" of memory and have them "debate" to reach the most accurate version:

  • Memory fusion: Combine contradictory memories into a synthesis.
  • Dialectic reasoning: Thesis (current memory) + Antithesis (new information) → Synthesis (updated memory).
  • Honcho: Memory fusion with per-source confidence scoring.

3.3 FTS5 / Full-Text Search vs Embeddings

FTS5 (SQLite): Exact, fast for keywords, low overhead. Ideal for specific errors, IDs, technical names.

Embeddings: Understands semantics, handles synonyms, searches by concept. Expensive, requires infrastructure.

Hybrid: SQLite + fts5 + vector extension, pgvector + pg_trgm. Hermes usa session_search que combina FTS5 + embeddings.

3.4 Memory Budgets and Automatic Compression

  • Token budget: Token limit for total context.
  • Memory count budget: Limit on stored memories.
  • Storage budget: Disk space limit.

Implementations: Hermes (auto compression to 20% when reaching 50% of limit), MemGPT (per-layer limits), LangMem (per-session budgets).

4. Evaluation and Benchmarks

4.1 How Do You Measure If Memory Works?

Retrieval metrics:

  • Recall@k: Proportion of relevant documents in top-k results.
  • Precision@k: Proportion of relevant results in top-k.
  • MRR (Mean Reciprocal Rank): Average of the reciprocal rank of the first relevant result.
  • Faithfulness: How faithful the generated response is to the retrieved memory.
  • Answer relevance: How relevant the answer is to the original query.

Agent memory metrics:

  • Memory utilization: Proportion of memories the agent effectively uses.
  • Memory accuracy: How accurate the stored memories are.
  • Memory retention: How long useful information is retained.
  • Memory interference: How much new memory negatively affects old memory.

Benchmarks adapted from RAG: RAGAS (faithfulness, answer relevance, context precision), HELM (holistic evaluation), MT-Bench (multi-turn).

4.3 Common Pitfalls

1. Stale Memory

Old memory is no longer accurate but keeps being used. Mitigation: Decay weighting, periodic review, versioning.

2. Memory Explosion

The amount of memory grows exponentially, slowing down retrieval. Mitigation: Memory budgets, auto pruning, consolidation.

3. Context Pollution

Irrelevant information gets included in context, distracting the LLM. Mitigation: Retrieval router, relevance filtering.

4. Memory Hallucination

The agent "remembers" things that never happened. Mitigation: Source verification, confidence scoring.

5. Fragmentation

The same information is stored multiple times. Mitigation: Deduplication, memory fusion, canonical storage.

5.2 Detailed Analysis

Hermes Agent

  • Strengths: System de skills robusto con curator automático, compresión de contexto automática, multi-plataforma (10+ gateways), auto-mejorable, plugin system extensible.
  • Weaknesses: Basic retrieval (no auto router), manual memory management.
  • Setup: curl -fsSL install.sh | bash — very low.
  • Repo: NousResearch/hermes-agent (~150k stars)

MemGPT (Claude)

  • Strengths: Mature memory layer architecture, auto memory management, solid academic paper.
  • Weaknesses: Requires own setup, dependency on external infrastructure.
  • Paper: arxiv.org/abs/2307.08653

Aider

  • Strengths: Git as implicit memory (change history), simple, effective for coding.
  • Weaknesses: No semantic memory, no retrieval.
  • Repo: paul-gauthier/aider

OpenDevin

  • Strengths: File system as persistent memory, secure sandbox, multi-agent.
  • Weaknesses: No semantic memory, basic retrieval.
  • Repo: All-Hands-AI/OpenDevin

LangGraph + LangMem

  • Strengths: Maximum flexibility (programmable), LangMem supports multiple backends.
  • Weaknesses: Requires programming the entire memory flow, steep learning curve.
  • Docs: langchain-ai.github.io/langgraph

CrewAI

  • Strengths: Multi-agent with defined roles, simple to use.
  • Weaknesses: Very limited memory, no advanced retrieval.
  • Repo: crewAIInc/crewAI

AutoGen (Microsoft)

  • Strengths: Conversational multi-agent, integration with Microsoft tools.
  • Weaknesses: Basic memory (chat history only), no retrieval.
  • Repo: microsoft/autogen

5.3 Recommendation for SRE with Self-Improving Production Agent

Scenario: An SRE who wants an agent that remembers past incidents, learns from every deploy, self-improves over time, and runs in production with low latency and high reliability.

Recomendación: Hermes Agent + Honcho Memory + PostgreSQL/pgvector

Why:

  1. Self-improving: The skills system automatically creates new skills after complex tasks. The Curator keeps them updated.
  2. Persistent memory: Honcho or Mem0 provide memory fusion and dialectic modeling.
  3. Hybrid retrieval: session_search combines FTS5 + embeddings. pgvector can be added for advanced semantic search.
  4. Production: Multi-platform gateway (Telegram, Discord, Slack), cron jobs for monitoring, webhook triggers.
  5. Low complejidad: One-command setup, YAML config.

Papers — ArXiv
01
When Agent Evaluation Becomes Unreliable: An Empirical Study of Oracle Failures and Configuration-Dependent Measurement in an LLM Agent Benchmark
Agent benchmarks are software with oracles, and nobody audits the oracle. The authors inject seven defect classes into evaluation harnesses, detect all of them via state-integrity invariants and known-answer controls, then apply the audit to a real benchmark — where a reward function that mutates environment state before scoring turns out to be inflating results. Across 4,320 episodes, replay-based correction drops database-pass labels from 4,194 to 2,883 and measured success from 94.3% to 65.5%. [evaluation, benchmarks, reliability]
arXiv
02
Agentic Dependency Transformations: Lessons from an Exploratory Case Study of Flask
AI coding agents are starting to rewrite how a repository handles its third-party dependencies — including reimplementing library functionality as local code — and nobody has a taxonomy for what they are doing. This exploratory case study on Flask defines dependency transformation, shows how available context shapes an agent's dependency discovery, and yields five preliminary lessons plus a five-part research agenda. Early-stage, but it names a change that supply-chain tooling is not yet built for. [agents, dependencies, supply-chain]

Why It Matters
▸ The strongest paper today is not about models at all — it is about the software that grades them, and it finds a 29-point inflation in a headline success rate caused by one defective reward function. Read it alongside Codex Desktop's endless Crashpad dumps and the OpenCode credential leak: the layer between the model and the user is ordinary software, shipped fast, rarely audited. Every leaderboard number you quote this quarter inherits that risk.
▸ The response across the board is verification of the verifiers. Lean's kernel is now itself verified just as LLM-generated proofs push proof throughput up; Sphinx gates merges by interrogating the human on what the model wrote; the oracle-audit paper treats benchmark harnesses as testable artefacts with invariants. The pattern is consistent — trust is being pushed down a level, from outputs to the machinery that certifies outputs.
▸ Dependency transformation is the quiet story with the longest tail. If agents routinely reimplement or rewire third-party libraries, the review surface of a pull request stops matching the diff, and the OpenCode leak shows what happens when dev tooling itself is the compromise path. The Flask case study is preliminary, but the direction is clear — agent-driven supply-chain change arrives before the tooling to audit it.

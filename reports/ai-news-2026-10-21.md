## Papers — ArXiv

### MemDev-Bench: Does Memory Help Code Agents?

Memory systems for code agents promise reuse of earlier experience on evolving repositories, but existing benchmarks lack temporally valid histories and any control over whether prior tasks are actually relevant. MemDev-Bench pairs 555 base tasks with 4,869 relevance-annotated historical tasks from the same repositories, produced by an automated pipeline that makes earlier tasks executable and verifiable. The systematic evaluation across development stages gives the first reliable read on when memory pays for itself and when it is dead weight. **[code agents, memory, benchmarking]**

Sources: [arXiv](http://arxiv.org/abs/2610.27524v1)

### Object-Oriented Harness: Evolving Agent Harnesses through Object-Oriented Design

A single global agent harness struggles with heterogeneous tasks that need different execution strategies. OO-Harness evolves a hierarchy of harness classes — an agent writes specialised subclasses via inheritance from execution records, and a router trained on accumulated routing lessons picks one per task at test time. It takes best-in-comparison across three long-horizon benchmarks spanning business workflows, workspace tasks and tool use. **[agent harnesses, optimisation, long-horizon]**

Sources: [arXiv](https://arxiv.org/abs/2610.28380v1)

### Benchmarking LLM Agent Authorization Alignment

Agent evaluations measure task completion or harmful outcomes, so actions that exceed the authority a user delegated slip through unmeasured. AuthorizationBench builds 286 executable tasks from documented real-world cases and runs four models at two reasoning-effort settings across three harnesses in an authorisation-aware sandbox — 6,864 trajectories in total. Agents act out of authorisation in 19.2% of trajectories, with no conventional safety or privacy harm to flag it. **[agents, authorisation, benchmarking]**

Sources: [arXiv](http://arxiv.org/abs/2610.27548v1)

### Runtime Control for AI Agents: Closing the Evaluation--Execution Gap in Operational Workflows

An agent approval valid when issued may no longer authorise execution after facts, policy or authority change — the evaluation–execution gap. The paper specifies a state-bound runtime layer that separates probabilistic measurement from deterministic adjudication, binds each execution allowance to the decision-relevant basis of its approval, and invalidates and rechecks at dispatch. Eight failure modes, a reference architecture, and a scripted 42-case replay demonstrating the interventions. **[agent safety, runtime control, workflows]**

Sources: [arXiv](http://arxiv.org/abs/2610.27480v1)

### Pattern-Driven Evaluation of LLM Code Optimization

Evaluating LLM code optimisation by end-to-end speedup conflates genuine model reasoning with transformations a modern compiler would find anyway. PatternBench isolates compiler-transcendent optimisation across seven transformation classes, pairing runtime measurement with an AST-based faithfulness check that verifies the intended optimisation actually landed in the generated program. Frontier, open-weight and fine-tuned models show runtime speedup that does not survive the compiler — much of the reported gain was never the model's. **[code optimisation, evaluation, compilers]**

Sources: [arXiv](http://arxiv.org/abs/2610.24835v1)

### When Does Experience Memory Help Closed-Loop LLM Driving Agents?

Published gains for experience memory in closed-loop LLM agents cannot be trusted, because warmup-pool composition and prompt-token effects are controlled in none of the prior work. This controlled HighwayEnv evaluation resamples ten disjoint warmup pools and adds token-matched irrelevant-filler controls across flat retrieval, grid ports, an episodic temporal-graph memory and a consolidated rulebook. Four findings, each testbed-specific — and the headline memory gains shrink once the controls are in place. **[agents, memory, evaluation]**

Sources: [arXiv](http://arxiv.org/abs/2610.27714v1)

## Why It Matters

-   The memory papers converge on an uncomfortable result: MemDev-Bench and the driving-agent study both find that memory helps only when prior experience is genuinely relevant to the current task, and that headline gains deflate under token-matched controls. Read that alongside SlopCodeBench's verdict that maximum reasoning effort is harmful — the field keeps adding machinery whose value evaporates under proper controls. If you are shipping a memory layer this quarter, demand the resampled-pool ablation before you pay for it.

-   AuthorizationBench's 19.2% out-of-scope rate and the evaluation–execution gap paper describe the same failure from two angles: delegation boundaries erode silently, and an approval checked once at issue time is not an approval at execution time. That is precisely the lesson of today's incident news — WhatsApp baking hidden instructions into official docs, fabricated statistics flowing into cited answers, an intermediate CA compromised at the trust-store layer. Deterministic adjudication and runtime revocation are not compliance theatre; they are the only patterns that survive a changing world.

-   The measurement theme cuts across everything: PatternBench shows speedups that aggressive compilers already deliver being credited to models, while OO-Harness shows the harness — not the model — moving long-horizon numbers. Meanwhile DeepInfer's open-sourcing and Alibaba's 230% output-price hike push the same point from the serving side. The leverage in production LLM systems sits in the scaffolding and the runtime, and any benchmark that does not isolate it will mislead your next procurement decision.

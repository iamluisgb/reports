Papers — ArXiv
01
Trace2Eval: Contextualized Evaluation of Coding Agents from Real-World Traces
Coding-agent benchmarks built on static public tasks with reference patches and hidden tests diverge from how agents are actually used. Trace2Eval constructs benchmarks from real interaction trajectories: a multi-agent reconstruction system recovers the original user query, restores workspace files to their pre-interaction state, and rebuilds a trajectory-equivalent execution environment for a candidate agent to run against. Evaluation targets overall artifact quality on continually refreshed real workflows rather than pass/fail on fixed tasks. [coding-agents, evaluation, benchmarks]
arXiv
02
Memory-Aware Multi-Agent Architecture with LLM-based Orchestration for Conversational Recommendation
Conversational recommenders treat sessions in isolation and bolt LLMs on as single components, losing how user intent evolves across a session history. This architecture makes the LLM an orchestration layer coordinating intent refinement, query construction and interaction flow, with long-term memory as a first-class input to both routing decisions and semantic query formation. Evaluated via cross-session memory experiments and multi-turn simulations on Amazon data. [multi-agent, memory, orchestration]
arXiv
03
AttentionSwitch: Jailbreak Defense for LLMs via Joint Learning of Sparse Attention-Head Selection and Scaling
Fine-tuning for jailbreak resistance is expensive and risks catastrophic forgetting; existing head-level interventions decouple where to intervene from how to modify, optimising each in sequence. AttentionSwitch jointly learns sparse attention-head selection and the scaling applied there, on the premise that the optimal location depends on the intervention and vice versa. Avoids full-model fine-tuning and the capability degradation that comes with it. [safety, jailbreak, interpretability]
arXiv
04
Typed-Centrality Grounding for Agentic GraphRAG
GraphRAG systems treat knowledge graphs as homogeneous and retrieve by textual similarity, wasting the deterministic structure the graph already encodes. The paper adds a symbolic layer: centrality measures computed per node class, fed to an agent as deterministic grounding alongside similarity-based retrieval. Same instinct as the formal-methods-grounded code graphs appearing this week — structure you can verify beats similarity you can only sample. [graphrag, knowledge-graphs, symbolic-ai]
arXiv
05
Ensemble Methodology for Reference-Free Confidence Estimation in LLM-based Code Summarization
Judging whether an LLM-generated code summary is correct usually requires human-authored references, which legacy codebases rarely have. The method generates summaries from diverse models, has an LLM judge emit structured pairwise comparisons, and applies a calibrated aggregation rule that combines supportive evidence while penalising only corroborated contradictions. Inter-model semantic agreement stands in for the missing ground truth. [code-summarization, uncertainty, llm-as-judge]

Why It Matters
▸ The harness is eating the model. Amazon's claim of millions saved by swapping Sonnet 4.6 for a Strands Decider on routing-class workloads is the same argument Trace2Eval makes from the evaluation side: what moves your cost curve is not the frontier score but whether the orchestration layer is measured against real trajectories. Fable 5.2's 65 on Artificial Analysis is a benchmark record; the Decider decision is a line item. The papers this week — trajectory-derived benchmarks, memory-aware orchestration, reference-free confidence — are all building the measurement layer that makes such swaps defensible rather than anecdotal.
▸ Trust failures this week were scoping failures, not alignment failures. Gemini routing private Drive files to human annotators and ChatGPT Desktop forwarding an SSH agent to remote hosts are both systems handing credentials to components that never needed them. AttentionSwitch's tightly scoped head-level interventions and Typed-Centrality's deterministic symbolic grounding point the same direction: safety and retrieval mechanisms you can specify, audit and bound, rather than emergent behaviour you discover in an A/B thread of 484 comments — which is exactly how the Opus 5.5 nerf allegations surfaced, with no changelog to check against.
▸ Compute economics are repricing faster than model quality. TPU 8tx and 8i Max, CoreWeave debt above 16%, and a 4.6× spread on identical H100s mean the input side of the ledger is volatile in both directions while capability gains compress. DeepX's 5 W 100B-parameter inference claim and Meta's Muse Ember pitch efficiency-per-parameter as the contested frontier — and a silent change to a deployed model's thinking patterns, as users allege of Opus 5.5 on 3 November, is cheapest to detect precisely where you own the evaluation harness rather than renting the benchmark.

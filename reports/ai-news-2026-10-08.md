## Papers — ArXiv

### Correct Code, Broken Contributions? SWE-CC: Benchmarking Repository Policy Compliance for Coding Agents

Coding agents pass unit tests but routinely violate the contribution policies that decide whether a patch actually gets merged. SWE-CC converts developer documentation from 12 open-source repositories into 823 machine-checkable atomic policies, with deterministic checkers for code and process compliance. It separates 'tests pass' from 'a maintainer would accept this' — a distinction no existing SWE benchmark measures. **[coding-agents, benchmarks, software-engineering]**

Sources: [arXiv](http://arxiv.org/abs/2610.06193v1)

### HarnessSecurity-Bench: Do Security Mechanisms Really Protect Coding Agent Harnesses?

Coding agent harnesses mediate tool use and authorise actions, but nobody had systematically measured whether their security mechanisms work. The study builds a ten-mechanism taxonomy, assesses 400 harness-mechanism cells, and finds roughly half of confirmed implementations are opt-in — with closed-source harnesses showing substantial evidence gaps. A 23-task benchmark across five attack surfaces, evaluated on six leading harnesses, measures task utility and attack effects with separate deterministic oracles. **[security, agent-harnesses, benchmarks]**

Sources: [arXiv](http://arxiv.org/abs/2610.07639v1)

### LiveMACE: Process-Aware Evaluation of LLM Agent Capabilities in Evolving Markets

Outcome-only evaluation hides which capabilities actually produced an agent's results, especially in environments that shift under the agent. LiveMACEBench runs five frontier LLMs in live financial markets for 30 days under matched Tool Use, Persistent Memory, Rule Following and Multi-Agent Collaboration configurations, scoring both returns and mechanism-specific diagnostics from full decision traces. The headline finding is a pronounced outcome-capability gap: similar returns arise from markedly different behavioural patterns. **[agent-evaluation, benchmarks, live-environments]**

Sources: [arXiv](http://arxiv.org/abs/2610.09872v1)

### Harness Engineering for Software Engineering via Modular Executable Dev-Primitives

Terminal-access agents stay brittle on long-horizon workflows because they repeatedly reconstruct program state scattered across source, configs, tests and runtime, driving context explosion and semantic drift. Dev-Primitives pair repository artifacts with resident LLMs, turning passive files into active participants with agent-native interfaces that hold state locally. It is a structural answer to the context problem rather than a bigger-context-window answer. **[agent-harnesses, software-engineering, context-management]**

Sources: [arXiv](https://arxiv.org/abs/2610.07832v1)

### Cost-Efficient Theorem Proving via Agent Orchestration in Program Verification

LLM-generated code is fluent but carries no correctness guarantee, and theorem provers chase pass rates at whatever sampling budget it takes. CoCo-Prover reframes proving as metalevel decision-making under cost, joining AND/OR proof hypergraphs within declarations to a lemma-dependency graph across them. The target is the frontier question that matters at scale: not whether one theorem can be proved, but how many per unit of compute. **[program-verification, agent-orchestration, cost-efficiency]**

Sources: [arXiv](https://arxiv.org/abs/2610.09681v1)

### Reliability of LLM Judges for Evaluating Entity Alignment

LLM-as-judge is the default substitute for expensive expert annotation, but its reliability on structured prediction tasks was unmeasured. Across three frontier models, three datasets and four entity alignment systems, the study identifies anchor bias: exposing the system's decision label to the judge causally collapses its discrimination, with J-ROC-AUC swinging from 0.12 to 0.87. Any eval pipeline that shows judges the answer being verified is compromised by construction. **[llm-as-judge, evaluation, bias]**

Sources: [arXiv](http://arxiv.org/abs/2610.09554v1)

## Why It Matters

-   The field is quietly abandoning outcome-based evaluation, and these papers show why. LiveMACE finds identical returns from different behaviour; SWE-CC finds passing tests says nothing about merge-ability; the judge-reliability work finds that letting an evaluator see the answer destroys its discrimination. If you are still reporting pass@k as the whole story, your numbers are now the least informative part of your eval.

-   The harness has become the product, and it is under-defended. Docker shipping open-source agent tooling, Ronacher's codemode, and Dev-Primitives all treat the action space — not the model — as the engineering frontier. HarnessSecurity-Bench's finding that half of security mechanisms are opt-in lands the same week Meta and Microsoft move to curb Claude internally: enterprises are adopting agents faster than the guardrails around them are being verified.

-   Cost is becoming the axis of competition, not capability. Haiku 5.5 as a headline release, CoCo-Prover optimising proofs per compute unit, and on-device work like HGP all point the same way: the frontier model is a commodity, and the wins now come from orchestration, routing and memory that spend fewer tokens and fewer FLOPs per solved task. Tao's argument about valuing mathematical progress beyond benchmarks is the same complaint in a different register — the metrics we optimise no longer match what we actually want.

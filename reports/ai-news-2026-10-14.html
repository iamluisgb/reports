01
When Agent Evaluation Becomes Unreliable: An Empirical Study of Oracle Failures and Configuration-Dependent Measurement in an LLM Agent Benchmark
Agent benchmarks are software, and their test oracles can be wrong in ways no leaderboard reveals. The authors inject seven classes of oracle defect, detect all of them with state-integrity invariants and known-answer controls, then audit a real benchmark and find a reward function that mutates environment state before scoring. Across 4,320 episodes, repairing the oracle drops measured success from 94.3% to 65.5%. [agent-evaluation, benchmarks, reliability]

02
SWE-MISBEHAVIOR: Benchmarking and Mitigating Boundary Violations in Software Coding Agents
Coding agents pass tests while quietly violating boundaries — editing user files, corrupting environments, misreading dependencies. This 7.4K-sample taxonomy covers 11 misbehaviours across code generation, file management and system interaction, with an automated protocol. OpenHands and smolagents misinterpret dependencies in up to 98.5% of cases, modify user inputs unintendedly in 50.5%, and silently compromise environment integrity in 53%. [coding-agents, safety, benchmark]

03
Scaling Inference-Time Compute with Teams of Coding Agents
Multi-agent coding promises a new compute axis, but naive teams duplicate work and burn budget. The paper frames team design as compute allocation — where a lead delegates (planning, implementation or verification), which models, how many workers — and traces the reward-cost Pareto frontier on ProgramBench. Teams beat solo agents but cost three to seven times more; with the right allocation, a heavier team recovers the gap. [multi-agent, inference-scaling, cost]

04
StateHarness: Maintaining Evolving Project State for Long-Horizon Coding Agents
Long-horizon coding agents lose the thread: what problem is being solved, what has been learned, what remains unresolved. StateHarness is a runtime that keeps an evolving project brief outside model weights — recording hypotheses, decisions, repository relationships and unfinished work, and prompting searches for callers and tests affected by each change. No fine-tuning; the scaffolding carries the state. [coding-agents, long-horizon, harness]

05
Memory Echo in Single-Agent Long-Term Memory: Lifecycle Evaluation and Provenance-Guided Mitigation
Repeated retrieval and write-back let one historical claim occupy multiple positions in an agent's memory and sway answers without independent evidence — an echo effect borrowed from memory psychology. MEchoBench measures its emergence, resistance to correction and persistence across a memory lifecycle. The proposed Family–Provenance–Authority framework deduplicates by source before storage, treating provenance as a first-class memory operation. [agent-memory, provenance, benchmark]

06
Self-Evolving Agent Harness
Harnesses that revise their own prompts, tools and workflows while weights stay frozen are becoming the norm; this paper gives the process a formal footing. It separates update targets from proposal and admission mechanisms, models the search as evolutionary optimisation, and derives a generalisation bound plus a high-probability admission rule using fresh validation data. The rare attempt to say when self-modification is safe rather than merely impressive. [self-evolution, harness, theory]

Why It Matters
▸ The week's papers converge on an uncomfortable claim: the layer between model and task — the harness — is now the dominant source of both error and cost, and almost nobody audits it. An oracle bug alone moved a benchmark's headline success rate from 94.3% to 65.5%; coding agents break environment integrity in over half of flagged cases; agent teams buy quality at three to seven times the price unless allocation is designed deliberately. Read every published agent number as an upper bound until the scoring software has been treated like the safety-critical system it is.
▸ Memory is quietly becoming the second attack surface, after tool access. Memory Echo shows a single stale claim can replicate itself through retrieval and resist correction; the unlearning benchmark shows agents cannot reliably forget on request; the knowledge-graph retraction work shows deletion without downstream re-examination loses the plot. The common fix is provenance — knowing which source produced which stored fact — and it needs to be a storage primitive, not a post-hoc audit.
▸ The news supplies the hardware and institutional versions of the same lesson. Ledger's confirmed implant, an 11-year-old borrow-checker unsoundness and a bugged conference room are all failures of the trusted base beneath the thing you actually inspect — the wallet, the language, the meeting. Apple's idle-Silicon inference cloud is the optimistic flip side: distributed capacity is cheap, but it is another distributed system whose failure modes nobody has characterised. Capability keeps compounding; verification culture is not keeping pace.

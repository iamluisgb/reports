Papers — ArXiv
01
(When) Should a Software Factory be Lights-off? Benchmarking Code Review Agents on Bug Detection
Human review velocity is falling behind agentic code generation, so the question is whether review agents can carry a lights-off factory. CRBugBench mines 1,000 human-verified bugs from 98 open-source repos plus 800 tasks from proprietary industry repositories, pairing each bug with its introducing PR as a review task. SOTA agents detect a solid share of these bugs, but the benchmark gives the first honest denominator for how far autonomous review is from safe. [code-review, benchmark, coding-agents]
arXiv
02
Co-Modifying Application Code and Deployment Infrastructure: A Causal Study of AI Agent Pull Requests
Coding agents are benchmarked in sandboxes against local tests, but real features touch CI pipelines, containers and provisioning manifests too. The authors isolate the causal cost of dual-scope PRs — application code plus deployment infrastructure — across 26,999 PRs from AIDev v5 and MOSAIC-3M, six agent architectures, with a matched human baseline. Dual-scope agent PRs carry measurably higher integration overhead because agents lack deployment awareness and inject unverified dependencies into async pipelines. [coding-agents, ci-cd, evaluation]
arXiv
03
LongHarness: Advancing Agentic Reasoning over 100M-Token Corpora via Stateful Evidence Management
Corpus-scale agents accumulate evidence in an ever-growing interaction history, producing two failure modes: unbounded retrieval loops and evidence-state drift, where earlier findings stop informing the current conclusion. LongHarness makes the evidence-to-conclusion relationship explicit, using unresolved conclusions to steer further exploration. Model-agnostic and built for corpora far beyond any context window. [agents, long-context, harness]
arXiv
04
Competence-Aware Orchestration for LLM-Based Multi-Agent Systems
More multi-agent collaboration is not always better — richer coordination helps on hard queries but burns tokens and adds redundant interactions on easy ones. This two-stage framework models the backbone's task-conditioned competence, then adapts role activation and the communication graph accordingly. Average score of 93.81% across six benchmarks, with six backbones of varying competence showing the orchestration tracks capability rather than assuming it. [multi-agent, orchestration, cost]
arXiv
05
The Right Memory in the Wrong Context: Verifying Retrieval Admissibility in Long-Term Agent Memory
Long-term-memory agents can retrieve information that is true, relevant and forbidden — another principal's data, a policy violation, a stale lifecycle state. Standard recall and accuracy metrics cannot see this, since a correct answer may follow inadmissible prompt exposure. The paper introduces a three-status verification framework (admissible, inadmissible, unresolved) and reanalyses frozen top-20 rankings from two public memory benchmarks, tracking memory IDs through to target-level disclosure. [agent-memory, security, evaluation]
arXiv
06
DRYLAB-Bench: Benchmarking the Biosecurity Risk of Agentic LLM Mutation Design
Existing biosecurity evaluations test whether models possess hazardous knowledge, not whether agents can act on it — and tool augmentation may close that gap silently. DRYLAB-Bench is the first benchmark measuring LLM agents' high-risk biological mutation design capability, including when they are wired to specialised biological design tools. Dry-lab validation replaces the expensive or hazardous alternatives. [biosecurity, safety, agents]

Why It Matters
▸ The papers converge on a single finding: the model is rarely the failure point — the harness is. LongHarness names evidence drift, the orchestration paper shows blind collaboration wastes tokens, and the PR study proves agents that write fine code break integration because nobody taught them about CI. If you are scoping agent features this quarter, the risk budget belongs to state management and deployment awareness, not to model choice.
▸ CRBugBench lands on the same day as QGIS banning AI contributions and the 396-point 'you still have to think' essay, and the numbers explain both. Review is becoming the bottleneck agents cannot clear: the best agents catch a real share of verified bugs, but 'a real share' is not lights-off, and maintainers know it. Karpathy's 763-comment thread about divergent capability models is the same argument from the other side — the gap between what agents demonstrably do and what teams assume they do is now an engineering cost.
▸ The security story repeats at every layer: Zod's supply-chain compromise, defrosted fridge fleets, and the admissibility paper's finding that correct answers can follow inadmissible retrieval. In each case the vulnerable component is the trusted plumbing around the capable core — a lockfile, a device, a memory route. Pin versions, audit what your agents are allowed to recall, and treat every always-on dependency as an attack surface with your name on it.

## AI / LLM / Agents

### "The Log Is the Agent" — log-first architecture for LLM agents

Proposes treating the structured log as the central abstraction for agent state, replacing prompt stuffing. Log entries determine context — agents read from and write to the log.

Sources: [arXiv](https://arxiv.org/abs/2605.21997)

### "Better Models: Worse Tools" — Armin Ronacher on the AI tooling paradox

Argues that as models get smarter, tool quality degrades — developers over-rely on AI and skip traditional engineering rigor. Strong HN discussion.

Sources: [lucumr.pocoo.org](https://lucumr.pocoo.org/2026/7/4/better-models-worse-tools/)

### Mouse — Precision Editing Tools for AI Coding Agents

New tooling layer designed to give AI coding agents fine-grained editing capabilities, beyond line-level diffs.

Sources: [hic-ai.com](https://hic-ai.com/)

### Claude Code session/cache leakage between workspace instances

Reported on GitHub: potential cross-instance cache contamination in Claude Code workspaces. Privacy concern for multi-tenant environments.

Sources: [GitHub](https://github.com/anthropics/claude-code/issues/74066)

## Papers — ArXiv CS.AI

### Are Performance-Optimization Benchmarks Reliably Measuring Coding Agents?

Questions whether benchmarks like GSO, SWE-Perf, SWE-fficiency actually measure coding agent capability through runtime optimization patches. **[benchmark, coding]**

Sources: [arXiv](https://arxiv.org/abs/2607.01211)

### PACE: A Proxy for Agentic Capability Evaluation

Cheaper proxy evaluations for SWE-Bench and GAIA — full runs cost thousands and days; PACE aims to approximate results faster. **[agent, evaluation]**

Sources: [arXiv](https://arxiv.org/abs/2607.02032)

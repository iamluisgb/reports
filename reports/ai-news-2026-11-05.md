## Papers — ArXiv

### ServerBench: How can your coding agents design specialized LLM serving systems?

Tests whether coding agents can design the LLM serving infrastructure they themselves run on, scored in dollars per dollar — latency-qualified token value per dollar of GPU cost. Claude Sonnet 5.5 reaches 2.97 dollars per dollar on Gemma E4B, 4.87x the vLLM reference; 22 of 33 runs produce verified systems and 13 beat the strongest baseline. Stateful replay preserves session dependencies and an independent verifier checks every submission. **[benchmark, serving-systems, agentic-design]**

Sources: [arXiv](http://arxiv.org/abs/2611.06841v1)

### CompressionBench: How can your coding agents compress LLMs?

Frames model compression as a terminal agentic task: given a checkpoint, a storage limit and a time budget, the agent must produce compressed weights and executable inference code, with perplexity feedback guiding search. Across six agents and six model-size settings, 29 of 36 submissions pass independent verification; the best designs land at 3.4% average perplexity increase over BF16 and 77.33% downstream accuracy. A concrete measurement of whether agents can do real infrastructure work unattended. **[compression, recursive-self-improvement, benchmark]**

Sources: [arXiv](http://arxiv.org/abs/2611.06858v1)

### SlackBench: Benchmarking Agents on Collaborative Projects Grounded in Real Code Repositories

Existing agent benchmarks test isolated tasks; real knowledge work means reconstructing context from scattered channels, messages and evolving repository state. SlackBench evaluates agents on privacy-preserving reenactments of real academic projects, requiring joint reasoning over workplace communication and code. It targets the gap between toy task completion and the multi-party, stale-evidence reality of collaborative engineering. **[agents, benchmark, collaborative-workflows]**

Sources: [arXiv](http://arxiv.org/abs/2611.05512v1)

### On Turn-Level Best-of-N Sampling for Scaling LLM Agents

Long-horizon agent runs fail on single bad turns, so the authors apply best-of-N at the turn level: a generator proposes N candidate actions each turn and a selector model picks one before execution. Using off-the-shelf open-weight LLMs as both generator and selector on long-horizon terminal tasks yields 5-10% accuracy gains and materially better consistency across repeated attempts. A cheap inference-time lever that needs no fine-tuning. **[inference-scaling, agents, long-horizon-tasks]**

Sources: [arXiv](http://arxiv.org/abs/2611.06868v1)

### Graph-Mediated Large Language Model Systems in the Agentic Era

A survey of how graphs underpin LLM systems — structural reasoning, knowledge grounding, retrieval, memory — and increasingly execution dependencies and multi-agent communication. Its contribution is an operation-level role-locus taxonomy that separates what each graph operation does, which component computes it, and how its output is consumed. Useful scaffolding for anyone building GraphRAG-style stacks that are currently held together by convention. **[survey, knowledge-graphs, agent-systems]**

Sources: [arXiv](http://arxiv.org/abs/2611.05953v1)

### HLSClaw: Bringing Vibe Coding to High-Level Synthesis through Skill-Based Agentic Harness

LLM agents degrade sharply in high-level synthesis, where code restructuring, directive search and downstream hardware constraints are tightly coupled. HLSClaw reframes HLS optimisation as an agentic control problem: modular executable skills plus a feedback-driven orchestrator navigate the coupled search space instead of a fixed transformation pipeline. Evidence that harness design, not raw model quality, decides performance in domain-specific code generation. **[agents, high-level-synthesis, harness]**

Sources: [arXiv](https://arxiv.org/abs/2611.02784v1)

## Why It Matters

-   The benchmark papers share a thesis: static task suites are done, and the interesting question is whether agents survive contact with real environments — Slack channels with stale evidence, personas with verifiable obligations, serving systems that must actually serve. ServerBench and CompressionBench go further and close the loop, asking agents to build the infrastructure agents run on; the verified-run rates (22/33, 29/36) say this is no longer speculative. Set that against DoorDash's 'hundreds of orders' from external agents: agentic capability is compounding in the back office long before it shows up in consumer commerce.

-   Graphs and ontologies are quietly becoming the control plane for agents. Nvidia's auto-ontology tool, ArcRAG's construction-agnostic retrieval, SecureGARD's ontology of action semantics, certified crosswalks for digital twins — and now a survey that gives the whole area a taxonomy. The pattern is consistent: as agents gain tool access, teams are reaching for explicit structure to constrain what they do, because prompt-level defences do not compose. Expect the semantic layer to show up in your stack as a governance requirement before it shows up as a performance win.

-   The security thread runs from the Binance heist through IEEE Spectrum's technical-debt argument to OpenAI's thousand eliminated privilege-escalation paths: agents amplify whatever surface you hand them, including 40 years of legacy patterns. Anthropic's provable-inference work points the same direction from the model side — empirical evals are losing their status as sufficient assurance. The pairing that matters today is CompressionBench-style independent verification plus open weights like Kimi K3.1 Pro: when you can audit the model and the harness, trust becomes a property you engineer rather than a vendor claim.

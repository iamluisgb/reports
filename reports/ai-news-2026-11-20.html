Papers — ArXiv
01
How Much Should an Agent Remember?
Agents on long-horizon tasks fail in recurring procedural ways — wrong entity resolved, API mis-paginated, answer given when none was asked. The authors mine one to three lessons per episode from an agent's own trajectories, consolidate them into guidelines, and show on AppWorld — across models with 40-92% baseline task completion — that the right amount of memory is a tunable optimum, not a monotone gain. The pipeline ships in the open-source altk-evolve library and runs in IBM's CUGA agent and watsonx Orchestrate. [agent-memory, self-improvement, deployment]
arXiv
02
Validation-driven Deployment of LLM Inference Platforms for Agentic Workloads
Enterprises moving agentic workloads from closed APIs to self-hosted open-weight models have no reliable way to size infrastructure before rollout. This end-to-end evaluation pipeline shows that replaying captured traces reproduces per-session load within 1.18x at the 95th percentile, against 4.98x for live re-runs — recorded sessions give you a repeatable token-load profile that re-execution cannot. Code-coverage analysis of vLLM shows live, replayed and synthetic workloads cover complementary code paths, so no single workload type suffices for validation. [infrastructure, benchmarking, agentic-serving]
arXiv
03
SWE-Recreation: Benchmarking Coding Agents for Software Recreation
Coding agents are always told what to build; this benchmark asks whether one can use an unfamiliar product and then rebuild it. 54 real applications — 28 websites, 26 Android apps — with 1,446 hidden requirements covering stateful multistep workflows, where the agent sees only rendered pixels and acts through pointer and keyboard, no DOM, source or logs. Five frontier systems top out at a modest completion rate, with a fixed pixel-evidence judge grading workflows and a separate judge estimating exploration coverage. [coding-agents, benchmark, evaluation]
arXiv
04
CompAct-Bench: A Benchmark for Working-Context Compaction in Long-Horizon Agent Tasks
Long-running agents accumulate tool observations and intermediate decisions until the context window is the bottleneck, yet how well models compress that history while preserving task progress is barely measured. CompAct-Bench inserts compaction boundaries into successful trajectories, compresses the prefix with the model under test, and scores the downstream effect on task completion under controlled retention ratios. The metric is what matters: compaction quality judged by whether the same executor still finishes the job, not by summarisation fidelity. [context-management, agents, benchmark]
arXiv
05
DriftGuard: Online Memory-Drift Detection via Causal Attribution for LLM Agents
Persistent agent memory is an attack surface: one misleading retrieved memory can bend the whole execution path, and perplexity or retrieval relevance won't tell you which. Counterfactual attribution — replaying downstream execution per candidate memory — is the accurate method but blows the serving budget. DriftGuard's two-stage approach estimates each memory's causal contribution to drift online, addressing detection at real-time latency rather than offline audit. [agent-memory, security, causal-attribution]
arXiv
06
SCAFFOLD: Warrant-Preserving Evidence Transport for Reusable LLM-Agent Skills
A skill that worked yesterday may still execute today without being justified for reuse — tests cover only observable contracts, permissions change, oracles go missing between validation and invocation. The paper proposes the Warranted Reuse Claim: a versioned, defeasible authorisation binding a skill to its target context, evidence and identified defeaters, plus a discipline for deciding which historical evidence stays admissible after context change. Formal rather than empirical, but it names the reuse-trust problem precisely. [agent-skills, trust, cs-ma]

Why It Matters
▸ The papers this week cluster on a single question: what infrastructure makes an agent trustworthy enough to run unattended — memory that knows when to forget, compaction that preserves the task, serving pipelines that predict load before rollout, and skill reuse that carries its justification with it. None of this is model capability work; it is all the scaffolding that turns a demo into a deployment. The Anthropic IPO dominating the headlines is, in effect, the market pricing exactly this gap between capability and operability.
▸ The evaluation papers deserve more attention than any single result. SWE-Recreation shows frontier coding agents failing when the spec is hidden inside a running product rather than handed to them, and CompAct-Bench measures compaction by downstream task survival rather than summary quality — both are the kind of benchmarks that change which systems people pick, the way Gemini 4 Neon topping the Models Engineering Index is already doing. If you pin a model this quarter, the differentiator is degradation under realistic harness conditions, not leaderboard position on clean inputs.
▸ Security is arriving at the agent layer from both ends simultaneously: DriftGuard treats retrieved memory as an injection surface, SCAFFOLD treats reused skills as stale evidence, and meanwhile the day's operational news — a CVSS 9.8 in OpenSSL and pre-auth RCE in stock Rails — is the same failure mode one layer down. The UK's confirmed secret encryption order to Apple adds a jurisdictional constraint on top. Anyone wiring agent memory, skill reuse or tool permissions into an internet-facing product is inheriting a supply-chain problem they haven't yet inventoried.

## Papers — ArXiv

### Chronos Enables Code Agents to Reason over Software Evolution

Code agents work from a snapshot; the design decisions and compatibility constraints buried in merged pull requests stay invisible to them. Chronos distils PR history into structured experience cards linked by a typed graph of code-level, intent and organisational relations, then uses weighted multi-hop expansion to retrieve connected changes. The same memory drives patch generation and selection — a change agent and a validation-strategy agent each draft a patch, and an evolution steward picks between them after consulting history. **[code-agents, retrieval, experience-reuse]**

Sources: [arXiv](https://arxiv.org/abs/2610.11578v1)

### MemTrial: Learning When to Trust Memory in LLM Portfolio Agents

Memory-based agents credit experiences with the outcomes of decisions that used them — but in markets that outcome mostly reflects the day's market move, so the credit tracks the market, not the experience, and such agents often underperform a dumb equal-weight portfolio. MemTrial puts memory on trial: each decision is drafted under eight experience combinations from a fractional factorial design, and each experience is credited with its Banzhaf value — the shared market component cancels in the differences. A clean answer to credit assignment when the environment, not the agent, dominates the reward. **[memory, credit-assignment, agents]**

Sources: [arXiv](http://arxiv.org/abs/2610.11732v1)

### Use and Disuse: Intent-Structured Experience Consolidation for Memory and Learning in LLM Agents

Long-running agents drown in their own transcripts; carrying full working context forward does not scale past a single task. Hippocam structures ongoing work as nested intents — active context stays on the current intent, and completed intents are consolidated down to task-relevant outcomes and state, with recursive prefix consolidation handling long horizons. Deliberately selective memory, modelled on how human recall discards. **[memory, long-horizon, agents]**

Sources: [arXiv](http://arxiv.org/abs/2610.12124v1)

### Memory Type Varies: Empowering LLM Agents for Long-Term Memory with Diverse Strategies

Retrieval-based memory systems treat every memory alike, which is suboptimal when a factoid, a preference and a procedural lesson need different handling. The authors release TriMEM, a dataset with precise memory-type annotations across scenarios, and MemoType, which classifies each memory and routes it to a matching retrieval strategy. Typing before retrieval, rather than one embedding index for everything. **[memory, benchmarks, agents]**

Sources: [arXiv](http://arxiv.org/abs/2610.11573v1)

### Evaluating Local Language Model Agents for Reproducible Data Engineering

Most agent evaluations score isolated code generation; this empirical study asks whether locally deployed open-weight agents can produce correct, reproducible data-engineering artefacts end to end. Fifteen mobility-workflow tasks — discovery, connectors, enrichment, validation, reporting — are scored by deterministic checkers across model scale, quantisation, runtime and tool use, with a closed-loop workspace condition isolated as a variable. The failure taxonomy is the useful part. **[evaluation, local-models, data-engineering]**

Sources: [arXiv](http://arxiv.org/abs/2610.11482v1)

### SynCo: Data Synthesis Co-Training for Self-Evolving LLMs via Multi-Agent Reinforcement Learning

Self-evolving agents stall because their training data goes stale: tasks that were once hard become trivial while the genuinely difficult ones stay uninformative. SynCo jointly trains a Synthesizer and a Reasoner with multi-agent RL, so the task distribution tracks the agent's changing capability instead of drifting behind it. Co-evolution of curriculum and capability, not two pipelines bolted together. **[self-improvement, multi-agent-rl, data-synthesis]**

Sources: [arXiv](http://arxiv.org/abs/2610.11345v1)

## Why It Matters

-   Four of today's six papers are, at bottom, about the same problem: an agent's history is an asset it cannot currently spend. Chronos turns PRs into retrievable experience, Hippocam compresses transcripts into intents, MemoType sorts memories before retrieval, and MemTrial shows the deepest cut — naive outcome-based credit assignment actively teaches an agent the wrong lessons. The field has quietly moved from 'give the agent a vector store' to asking what a memory is for, how it should be typed, and whether the reward signal that formed it was even attributable to the agent.

-   The engineering around agents is maturing faster than the agents. Microsoft shipping MXC, Oxide raising $445M for on-prem hardware, and an empirical study of local open-weight agents on real data-engineering pipelines all point the same way: the harness, the sandbox and the runtime are becoming products in their own right, and the differentiator is shifting from model choice to how you gate, execute and verify what the model emits. The Anthropic false-tip story is the negative proof — an agent with a submission channel and no human review is an integration bug with legal consequences.

-   Be sceptical of the money. Typesafe AI at $7.5B and a consolidating edge-runtime market (Cloudflare–Deno) mean tooling roadmaps will be set by vendors with balance sheets, not by what the memory and credit-assignment papers are showing actually works. The research direction worth backing this quarter is selective, typed, attributable memory — none of it needs a new foundation model, and all of it compounds.

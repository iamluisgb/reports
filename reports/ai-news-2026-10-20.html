Papers — ArXiv
01
CXBench: A Benchmark for Process-Compliant LLM Agents in Regulated Customer-Experience Workflows
Tool-agent benchmarks score the final business state, so trajectories that hit the right outcome while skipping disclosures or consent count as wins. CXench grades outcome and process separately across six regulated domains, using rule cards tied to trace evidence and a hybrid deterministic-plus-LLM grader. Across seven models and 120 tasks, 55.5% of runs that pass outcome checks are false-passes on process. [agents, compliance, benchmarking]
arXiv
02
Same Simulation, Different Evidence: Where Retrieved Tool Output Costs LLM Agents Accuracy
Agent harnesses increasingly park long tool outputs in files and let the model search them on demand; this paper measures what that costs. Using the deterministic USGS geochemistry simulator PHREEQC — reports up to 846.8k characters, 158 execution-verified questions — GPT-5.1 and GPT-5.2 lose 11.3 and 7.9 accuracy points when reading via a section index instead of full context, while Claude Opus 4.6 and Sonnet 4.6 show no detectable loss. Replaying all 11,007 logged simulator calls shows the GPT models still compute the right value; they just answer from the wrong evidence. [harnesses, retrieval, evaluation]
arXiv
03
When Coding Agents Outpace Review: Evaluating PRD-Driven Development in Mature Enterprise Repositories
Issue-resolution benchmarks say little about whether an agent can deliver a full product requirement document inside a real enterprise codebase. PACE specifies 43 enterprise tasks with 750 expert-audited Code Points and evidence-based grading of PRD fulfilment. Across 11 model–scaffold configurations, scores land between 52.1 and 78.1, and the best — GPT-5.6-Sol — achieves complete delivery on just 14.0% of tasks, with incomplete implementation and missing integration the dominant failure modes. [coding-agents, benchmarking, software-engineering]
arXiv
04
Teaching Code Agents to Ask Without Leaking Private Code
Local coding agents that consult a stronger cloud model leak private identifiers, paths and source in the questions they ask. Utility-verified abstraction trains the agent to describe private entities by role and type, keeping a rewrite only if it discloses fewer private entities and the repair still replays from the same execution state. After training, the agent consults more often, not less — privacy and capability stop being a trade-off. [privacy, coding-agents, fine-tuning]
arXiv
05
RouterWorld: Scaling Conversational AI with Latency-Aware LLM Routing
Routing benchmarks assume full observability of every candidate model's output and treat latency as an afterthought. RouterWorld unifies 371k single-turn responses and 76k multi-turn agentic trajectories, grounds latency in hardware measurements rather than transient pricing, and formalises routing under partial observability with cold-start and voyage-style setups. A standardised judge protocol replaces the fragmented evaluation landscape it replaces. [routing, latency, evaluation]
arXiv
06
Tandem: Serving Hybrid Linear-Attention GUI Agents on Mobile NPUs
On-device GUI agents pay latency on every screen-read-and-act cycle, and checkpoint policies borrowed from chat continuation miss the reusable prefixes agent requests actually contain. Tandem is a runtime for hybrid linear-attention models on mobile NPUs that saves recurrent state at the right positions and keeps speculative-decoding rollback off the matrix unit, where its overhead outweighs decoding savings on short action outputs. The result is local GUI automation that keeps screen contents on the phone without per-action latency collapse. [on-device, serving, gui-agents]

Why It Matters
▸ Three of today's papers attack the same blind spot from different angles: outcome metrics flatter agents. CXBench finds 55.5% of outcome-passing runs violate process requirements; PACE finds best-in-class complete delivery at 14.0% on real enterprise PRDs; the PHREEQC study shows models computing correct values and then answering from the wrong evidence. The 517-comment HN thread on shipping AI-written code nobody could have written by hand is the practitioner version of the same finding — review practices haven't caught up with what agents actually produce. Expect process-level and evidence-level grading to move from research into CI within the year.
▸ The harness is now a load-bearing, model-specific component. File-based tool-output retrieval saves context but costs GPT-5.x double-digit accuracy while leaving Claude untouched — the same trade Rubi and Keel make in today's news when they cache codebase structure to avoid re-reads. Anyone building agent infrastructure should treat context-management choices as experiments to run per model, not defaults to inherit, because the failure is silent: the agent still computes the right answer and then cites the wrong thing.
▸ The trust perimeter is being redrawn around deployment choices rather than model names. The DHS ban on DeepSeek, Project Discovery's write-up on abliterated models as a local-deployment liability, and UVA's result that privacy-preserving cloud consultation can increase capability all point the same way: who sees your data, and what refusal training a local model kept, are now engineering decisions with security consequences. Tandem's on-device NPU runtime is the architectural answer — keep sensitive context local and pay for capability in systems work instead of exposure.

## Papers — ArXiv CS.AI

### ExploitBench: Capability Ladder for LLM Security Agents

Proposes exploitation as a progressive capability ladder from single-bug execution to full system compromise — a more nuanced benchmark than binary "crash vs success." **[security, LLM, agent, benchmark]**

Sources: [arXiv](https://arxiv.org/abs/2605.14153)

### The Misattribution Gap: Memory Poisoning in Agentic AI

Memory-layer attacks produce behaviors indistinguishable from model failure, causing defenders to apply wrong fixes. Structural flaw in multi-agent pipelines. **[security, agent, LLM]**

Sources: [arXiv](https://arxiv.org/abs/2605.22842)

### Blind Spots: Domain-Camouflaged Injection Attacks

Injections mimicking domain vocabulary and authority structures evade detectors calibrated on template-based payloads. **[security, LLM, agent]**

Sources: [arXiv](https://arxiv.org/abs/2605.22001)

### Constraint Decay: Fragility of LLM Agents in Backend Code Gen

LLM agents fail under strict architectural constraints (patterns, databases, ORMs) — production-grade code generation remains fundamentally brittle. **[agent, LLM, code]**

Sources: [arXiv](https://arxiv.org/abs/2605.06445)

### Verifiable Agentic Infrastructure

Proposes proof-derived authorization to prevent syntactically valid but semantically unsafe actions by autonomous AI agents. **[agent, security, infra]**

Sources: [arXiv](https://arxiv.org/abs/2605.15228)

### Epistemic Calibration for Multi-Agent Systems

## Why It Matters

-   Supply chain is the new battlefield. The Grafana breach via TanStack npm shows that even observability platforms — the tools we use to detect breaches — are vulnerable. Every npm dependency is a potential vector.

-   Agentic infrastructure is being built in real time. Cloudflare+Anthropic, Verifiable Agentic Infrastructure papers, and the Misattribution Gap all point to the same conclusion: the security model for autonomous agents needs fundamentally new primitives, not prompt engineering.

-   LLM security evaluation is maturing. ExploitBench, Frontier LLM Security benchmarks, and Constraint Decay all signal a shift from "can it write code?" to "can we trust it in production?" — the question that matters for SRE.
